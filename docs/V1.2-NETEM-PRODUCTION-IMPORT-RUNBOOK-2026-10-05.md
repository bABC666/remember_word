## 失败、中断与回退边界

- 提交前异常／进程退出：SQLite恢复未提交事务，库创建也回滚；副本已验证第20次词条 INSERT 异常和 exit 86。先静止写入、留存现场，再检查 `public_import_run` 中同计划摘要与目标库。有完整已提交 run 则重试只返回 `already_applied`；没有 run 时确认既有业务行未改，再重试**同计划**。出现孤立空系统库或不一致 run 即停止，不把半成品当成成功，也不自动删库。
- 在导入前后仍写入静止、并且确认没有任何新用户数据时，可以整库恢复**当次**已校验 backup。先停所有连接，保留失败现场主库/WAL/SHM（精确绝对路径）并确认仍在固定 data 目录；将备份恢复到固定主库并隔离旧 sidecar，不能把旧 WAL 接到恢复后的库。复核 revision、完整性、外键及当次原行快照，再按原配置启动。不得执行 schema downgrade；恢复前需确认写入静止的证据，否则走撤下。
- 从账号验收或开放使用产生新数据之后，**禁止整库恢复历史备份**。先作新的 online backup，再短暂静止写入；仅把该导入 run 对应、owner=NULL、source_type=netem 的公共库 `visibility` 改为 `private`，保留所有词条、证据、学习状态、review_event、选库指针、用户、私有库、会话。新的队列可读性过滤排除它，公共列表／选库／推荐／显式请求也不再提供它。原有个人历史记录仍保留来源证据，这是撤下公共供给，不是抹掉个人历史。
