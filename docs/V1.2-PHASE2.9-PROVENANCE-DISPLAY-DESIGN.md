# V1.2 Phase 2.9 · 「数据来源与许可」展示设计（首次交付设计稿 · 未实施）

> **性质**：只读设计切片交付物。本文**不是**授权声明、**不是**验收记录、**不是**可提交的 manifest。
> **本切片没有做**：没有改前后端代码；没有新增 migration；没有改正式 manifest；没有运行导入、`confirm`
> 或任何生产库操作；没有抓取任何新来源；没有提交任何授权询问；**无代码改动，因此没有跑 `check.ps1`**。

> 「来源授权是否成立」等待人工裁定的事项全部列在 **§6 阻断**，本设计**不**对其中任何一条下结论。

## 2. 最小界面入口（取舍与理由）

**决定 1：新增一个登录态路由 `/sources`「数据来源与许可」，但不加第 7 个侧栏项。**

- 理由（实测）：侧栏 6 项已被 F-6 判定为手机端超宽，再加一项会继续挤压底栏与「退出登录」的位置。
- 入口三处，均为**加一行**的最小改动：
  1. `SettingsPage` 「本地数据」section 下方一行链接 `→ /sources`（管理员/普通用户都可见）；
  2. 词条详情页的来源区块内链（§3 L1/L2）；
  3. `HelpCenter` 使用说明里一句「词库内容来自哪些来源、各自许可见『数据来源与许可』」。
- 不加新导航项的备选（供负责人挑）：在 `AppShell` 的 `sidebar-foot` 内加一条文字链。

**决定 2：页面结构 = 一句总述 + 逐来源卡片（每张卡一个 `#source-<source_id>` 锚点）。**

每张卡显示：来源名、`publisher`、`version`、`obtained_at_utc`、`license_id`、许可链接、`license_text_sha256`
（前 12 位）、`use_scope` / `display_scope` 的**当前原文**、以及"本实例对这份来源做了什么修改"的一句话
（内容来自已确认的 `entry_concise_meaning.derivation_note` 汇总 + 来源页固定文案，**不是**运行时推断）。

**决定 3：许可链接不进数据库，用静态映射；映射缺失时只显示 `license_id` 文本，不猜 URL。**

- 理由：库里只有 `license_id`（自由文本 ≤80）与许可文本**指纹**，没有 URL 列。URL 属于"这份许可是什么"
  的公共事实，可以静态维护；但**不能**由界面反过来推出"我们使用它已合规"。
- 已出现的取值举例：`CC-BY-NC-SA-4.0`、`CC-BY-SA-4.0+GFDL`、`CC-BY-SA-4.0`
  （`manifest-p29x-isolated-prov.json:22,47,70`）。其中 `+GFDL` **不是单一 SPDX 标识符**（核对表 §3 已记为待裁定），
  静态映射必须能表达"双许可"而不是硬塞一个。

**决定 4：页首必须有一条 fail-closed 状态横幅 —— 界面显示"声明了什么"，不显示"已合规"。**

- 三份来源的 `use_scope`/`display_scope` 现为「预演草案·未获批准…」；预检会把含 `未获批准` 等固定子串的
  声明判为 `explicitly_unapproved` 并**阻断**（`services/public_lexicon_target_preflight.py:57-60,252-260`；
  关键词表见核对表 §0，已修为 fail-closed）。
- 因此横幅文案固定为：「以下来源的使用范围声明**尚未获批**，本页只如实转述声明内容，不代表授权结论。」
- **禁用措辞**（界面文本层面）：不得出现「已获授权」「符合 CC 要求」「官方授权」；词频一律只能说
  「来源自述的混合考试语料计数」，**不得**称「考研真题词频」（报告 §5.1、§3.1.1）。

## 3. 词条详情中的回查方式（逐词来源不同也成立）

**L1 · 行内（改 `ConciseMeaningList` 的现有那一行）**：把「来源位置 primary:2」升级为
「来源：<从证据行解析出的来源名> · 第 N 行」+ 链接「该来源的许可」→ `/sources#source-<source_id>`。
来源名取自 `source_artifact.publisher`（或 `name`），**不硬编码**。

**L2 · 本词条来源（`<details>`「本词条的来源与修改」）**：逐字段列出

| 列 | 数据来源 |
|---|---|
| 字段（单词 / 释义 / 音标 / 原书原文） | `entry_source_evidence.field_kind` |
| 来源 | `source_artifact.publisher` + `version` |
| 许可 | `license_id` + 静态映射链接 |
| 该字段的来源原文 | `entry_source_evidence.raw_text` |
| 是否被采纳 | `decision` / `selected_for_default` / `selection_order` |
| 是否修改 | 措辞级：`provenance_kind` + `derivation_note`（沿用现有标签）；来源级：来源页的固定修改说明 |
| **固定修订回查** | 仅 `zhwiktionary-pinned-oldid`：按 `row_locator` 读归档文件的同一行取 `zh_oldid` → `…/w/index.php?oldid=<oldid>` |

**L3 · 降级（必须实现，否则等于造假）**：下列任一情况，显示「该词条的来源记录不完整」并写明缺哪一项，
**不生成任何链接、也不静默省略整块**：

1. 该词条没有任何 `entry_source_evidence` 行（图片导入词、旧数据、或**尚未发生任何真实导入**，见 §5）；
2. `source_locator` 的 source_id 不在该词库的来源清单里；
3. 归档文件不可读 / 行号越界 / `zh_oldid` 为空；
4. `license_id` 没有静态映射（此时显示文本，不给链接）。

**L4 · 不变量**：`source_raw` 与 `source_meanings` 仍原样展示，「原书原文」区块保持不变。逐词回查是**加**入口，
不改写、不覆盖、不由 AI 生成任何来源文本。

## 4. 缺什么（按「要不要动 schema」分开，本切片一律**不做**）

| 类别 | 缺什么 | 影响 |
|---|---|---|
| **无 migration 可做** | 词库级来源清单（`run.target_lexicon_id` → `run_source` → `source_artifact`）；逐词逐字段回查（`entry_source_evidence`）；许可文本指纹；按行解析 `oldid` | 本设计的**核心能力全部落在这里** |
| **需要新迁移（列出以便裁定）** | ① `lexicon_entry` 无来源列；② `entry_concise_meaning.source_locator` 是**自由文本、无 FK**（`primary:2` 只是约定，`models.py:844`）；③ 接口不返回 `source_evidence_id`；④ `source_artifact` 无许可 URL、无**署名文本**字段；⑤ 没有 `oldid`/页面 URL 列 | ①②⑤ 是"每一行来源都可靠可查"的结构性缺口；③ 是小改但属接口契约变更；④ 决定署名文字能否由数据驱动 |
| **数据还不存在** | **从未发生过一次真实导入**（预演均为 `file_only_preview`）。因此 `source_artifact` 与 `entry_source_evidence` 现在都是**空表**，逐词回查**无数据可显示** | 这正是 L3 降级必须是一等公民的原因 |
| **界面能力缺口（报告 §8.4/§10 已登记）** | 前端没有来源页；`lexicon` 无许可字段；无逐字段来源列 | 本设计补齐入口与展示，不补 schema |
| **上游未入清单** | zh.wiktionary 候选里夹带的 CC-CEDICT / `{{翻譯}}` 内容（隔离账本 111 条 / 32 词，命中 10 词）；DBnary 作为 WikDict 的中间上游 | **不能在界面上装作它不存在**，见 §6 B2/B5 |

## 5. 阻断（**必须人工裁定**；界面设计不替代授权结论）

| # | 阻断 | 为什么界面过不去 |
|---|---|---|
| **B1** | **三份来源的 `use_scope`/`display_scope` 全部未批准**（核对表 Q1–Q2） | 是负责人的授权决定，无文件可证；预检 fail-closed。界面只能显示"未获批"，**不能**把"我们的产品计划是非商业"写成"许可要求已满足" |
| **B2** | **NC（NETEM）/ SA 是否及如何采用 / BY 的署名对象**（Q8、Q9、Q10、报告 §6.1(2)、§8.5） | NC 判据是用途性质而非人数；SA 取决于汇编还是改编、以及实际发布方式（报告明确不下结论）；zh.wiktionary 的署名对象是**各页贡献者**而非基金会 —— 写错就是把 BY 履行到错误对象上 |
| **B3** | `license_id` 的书写规范（SPDX 单值 vs `CC-BY-SA-4.0+GFDL`）、zh.wiktionary 的 `license_text_sha256` 留空是否可接受（Q5、Q6、Q7） | 直接决定静态许可映射表长什么样；留空时界面**只能**显示"无许可文本指纹"，不能显示一个占位摘要 |
| **B4** | **CC-CEDICT / `{{翻譯}}` 上游的归属与署名**（Q14；7 词还是 10 词未裁） | 未裁定前，涉及这 10 个词的来源块**不得**只标 zh.wiktionary 一个来源 |
| **B5** | DBnary 的再分发条件（Q15） | WikDict 卡片的署名链写到几层，取决于此 |
| **B6** | `obtained_at_utc` 的语义（留档 mtime vs 来源方提交时刻，Q11）、版本串写法（Q12） | 决定来源卡片上"版本/取得时间"两行的含义；两种语义**不可混用** |
| **B7** | 文本证据指纹口径（CRLF/LF，Q13；同一 TSV 12,350 B 与 12,249 B 两个"正确"摘要） | 界面若显示指纹，必须先定口径，否则复核者无法判断对错 |
| **B8** | **证据留档位置**：`.gitignore` 覆盖的 `test-artifacts/` + 原临时目录（核对表 §9 阻断 5） | `oldid` 回查**依赖**这份归档可读；归档一失，B 类来源的逐词回查全部退化为 L3 降级 |
| **B9** | 全量（5,528 词）`oldid` 与各来源版本固定**未落到交付物**（§9 阻断 7） | 首次交付若只覆盖 300 词切片，来源页必须写明覆盖面，不能暗示全量已固定 |
| **B10** | **是否把"加来源页"纳入首次交付范围**（核对表 Q2 附属决定） | 三份来源的 BY 义务都要求应用内可见的来源与许可页；不纳入，则 `display_scope` 候选文字**无法被完整履行** |
| **B11** | 未经裁定不得展示的项：NETEM `释义` 列 `[授权未明]`、ECDICT/kajweb 系、真题语料（核对表 §6） | 界面**不得**为这些内容生成来源行或"来源"标签 |

## 6. 可验证的验收标准（先定标准，再谈实现）

| # | 标准 | 验证方式（不改 schema、可自动化） |
|---|---|---|
| AC1 | 登录后 ≤1 次点击可从设置页或任一词条详情到达 `/sources`；**未登录**访问 `/sources` 得到登录页且不泄露任何来源字符串 | 路由/组件测试 + 未登录渲染断言（`App.tsx:86-90` 的 Gate 行为） |

| AC3 | 有映射的 `license_id` → 链接 `href` 等于规范 URL；**无映射**时只显示 `license_id` 文本，DOM 中**不存在**指向该许可的 `<a>` | 两种输入各一条断言（含负向断言） |
