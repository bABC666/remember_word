# V1.2 Phase 2.9 · 「数据来源与许可」展示设计（首次交付设计稿 · 未实施）

> **性质**：只读设计切片交付物。本文**不是**授权声明、**不是**验收记录、**不是**可提交的 manifest。
> **本切片没有做**：没有改前后端代码；没有编写 migration（只**规定**它）；没有改正式 manifest；没有运行导入、
> `confirm` 或任何生产库操作；没有抓取任何新来源；没有发送授权询问；**无代码改动，因此没有跑 `check.ps1`**。
>
> **唯一目标**：设计首次交付所需的「数据来源与许可」展示方式 —— 登录用户能找到来源、许可链接、适用署名
> 与修改说明；**对逐词来源不同的释义，能回查对应的原页面或固定修订**。
>
> **⚠ 界面不能代替授权结论。** 本文只设计「把已声明的来源与许可如实显示出来，并把没答案的部分显式留白」。
> 「来源授权是否成立」等待人工裁定的事项全部列在 **§6 阻断**，本设计**不**对其中任何一条下结论。
>
> **本版（第二次修订）改了什么**：为**逐词固定修订链接**选定了一条随应用交付、可验证的取值路径（**§3**），
> 并因此**明确要求一处最小 schema 变更**（新增一列 + 一条 migration）。上一版把"按行去归档文件里取
> `oldid`"当成回查路径 —— 那条路径依赖 `test-artifacts/`，**本版把它降级为一次性审计手段，并从渲染路径中移除**。

## 2. 最小界面入口（取舍与理由）

**决定 1：新增登录态路由 `/sources`「数据来源与许可」，但不加第 7 个侧栏项。**
理由：侧栏 6 项已被 F-6 判定为手机端超宽。入口三处，各加一行：① `SettingsPage`「本地数据」下方；
② 词条详情来源区块内链；③ `HelpCenter` 一句话。备选（供负责人挑）：`AppShell` 的 `sidebar-foot` 加一条文字链。

**决定 2：页面 = 一句总述 + 逐来源卡片（`#source-<source_id>` 锚点）。**
每张卡显示 `publisher`/`version`/`obtained_at_utc`/`license_id`/许可链接/`license_text_sha256`（前 12 位）/
`use_scope`/`display_scope` 原文/本实例对它的修改说明（来自已确认 `derivation_note` 的汇总 + 固定文案）。

**决定 3：许可链接用静态映射；映射缺失时只显示 `license_id` 文本，不猜 URL。**
库里只有 `license_id`（自由文本 ≤80）与许可文本**指纹**，没有 URL 列。已出现的取值：
`CC-BY-NC-SA-4.0`、`CC-BY-SA-4.0+GFDL`、`CC-BY-SA-4.0`（`manifest-p29x-isolated-prov.json:22,47,70`）；
`+GFDL` **不是单一 SPDX 标识符**（核对表 §3 待裁定），映射必须能表达"双许可"。

**决定 4：页首固定 fail-closed 横幅 —— 界面显示"声明了什么"，不显示"已合规"。**
三份来源的 `use_scope`/`display_scope` 现为「预演草案·未获批准…」，预检会把含 `未获批准` 等固定子串的声明判为
`explicitly_unapproved` 并阻断（`target_preflight.py:57-60,252-260`）。横幅文案：
「以下来源的使用范围声明**尚未获批**，本页只如实转述声明内容，不代表授权结论。」
**禁用措辞**：不得出现「已获授权」「符合 CC 要求」「官方授权」；词频只能说「来源自述的混合考试语料计数」，
**不得**称「考研真题词频」（报告 §5.1、§3.1.1）。

## 3. 逐词固定修订链接：取值路径的选定（本版核心）

### 3.1 三个候选，以及实测约束

| 方案 | 做法 | 是否需要新 migration | 链接的真实性来自哪里 |
|---|---|---|---|
| **A · 确认时把修订固化进证据行** | 清单声明"哪一列是固定修订、用什么 URL 模板"；确认时按 locator 读出并写入证据行 | **需要：+1 列**（§3.3） | 库内数据：`(file_sha256, mapping_sha256, line)` 冻结 + 确认时的**重推导门** |
| B · 把固定版来源文件作为受控运行数据交付 | 部署带来源文件；渲染时按 `row_locator` 读该行取修订 | 不需要（复用 `file_sha256`+`row_locator`） | 运行时文件：每次渲染重算文件指纹 |
| C · A 为主、缺了就回落到 B | 两者都留 | 需要 +1 列 | 取决于运行环境 |

### 3.2 选定：**方案 A**

**理由（逐条对回实测）**

1. **确认那一刻是唯一同时具备"可信字节 + 冻结映射 + 人工裁定"的时点**，而且今天的确认路径**已经**在重读字节、
   重算 `mapping_sha256`、按 locator 重取值为（`confirm.py:213-283`）—— 在这里多推导一个修订号，是**顺路**，
   不是新机制。
2. **只有 A 能让链接"随应用交付"**：`/sources` 与逐词链接所需的全部输入都在 `data/vocab.db` 里，
   跟着现有备份走。B 要求每个部署额外携带 1.1 MB（NETEM）+ 0.28 MB（zh 留档）+ 1.5 MB（WikDict zip）的来源文件，
   并新增备份项。
3. **只有 A 让渲染路径不需要读文件**：B 要求 Web 进程新增一条"读源文件 + 重算 SHA-256"的运行路径
   （今天只有 CLI 读源文件，且 `preview_file` 是整文件读取、8 MB 上限）。
4. **B 会重新引入本版要消除的那条依赖**：`test-artifacts/` 是 `.gitignore` 覆盖的目录，原证据还在会话临时目录
   （核对表 §9 阻断 5）。把"链接是否可信"建立在它上面，等于把可交付性押在一个不随应用交付的目录上。
5. **B 对来源 C 完全无用**（WikDict 没有逐词修订，只有一个包版本），因此不通用；A 用"`value` 形式的固定修订"
   同时覆盖 A 类（commit 级）与 C 类（包级），一条机制三种形态。
6. **B 还多一层未决的许可含义**：把来源文件本身随应用分发是一次**再分发**行为，落在 B1/B2 待裁定范围里；
   A 只分发**由来源派生的展示字段**（与现有 `source_raw`/`source_meanings` 同类），不改变这个问题的形状。
7. **方案 C 不选**：它保留两者的风险，并让"链接是否可信"取决于运行时环境，无法用一条验收标准说清。

**⚠ 选 A 不等于授权成立**：A 只保证"这个链接指向我们**声称**使用的那一版"。该声明是否被许可、`use_scope`/
`display_scope` 是否获批，仍是 §6 的 B1–B11。

### 3.3 最小 schema 变更（唯一一处）

```
0010_entry_source_revision   (down_revision = "0009_entry_concise_meaning")

+ entry_source_evidence.source_revision   String(64)  NOT NULL  server_default ""
+ CHECK (source_revision = trim(source_revision))
      name = ck_entry_source_evidence_revision_trimmed
downgrade: 精确移除该列（只动本切片新增的列，不动任何既有列或行）
```

- **为什么必须加列，而不是塞进现有列**：把修订号写进 `source_locator`（自由文本 ≤200）或 `derivation_note`
  之类既有列，会把**机器可解析的链接**退化成人类可读的散文 —— 没有形状/长度校验、没有重推导门、
  无法与 `decision` 绑定、接口无法稳定解析。**这正是本次要消除的问题**，所以不为"零 migration"而妥协。
- **为什么只加一列**：URL 模板随映射一起被 `mapping_sha256` 冻结、并且已经存在 `source_artifact.mapping_json`
  里；artifact 只增不改，所以模板不可能对既有证据行改口。证据行只需存**该行的修订值**；
  完整 URL 由**服务端**合成，客户端不拼接。
- **不加索引**：查询路径是 `lexicon_entry_id`（已有索引）→ 证据行 → `source_artifact_id`（已有索引），
  修订列不作为过滤条件。
- **迁移本身要遵守既有纪律**：`0008`/`0009` 尚未发布前的同类纪律见 `0009` 的文档头
  （`alembic/versions/0009_entry_concise_meaning.py:27-38`）；新增 `0010` 会让单头断言
  （`tests/test_concise_meaning.py:1244-1253` 现期望 `0009`）与 `test_downgrade_guard.py` 的表/列集合需要同步更新。

### 3.4 取值链：清单 → 计划 → 确认 → 库 → 接口

| 步 | 做什么 | 失败行为 |
|---|---|---|
| 清单 | 每份来源新增**非字段**声明 `revision`，与 `columns` 并列。二选一：`{"column": "zh_oldid", "url_template": "https://zh.wiktionary.org/w/index.php?oldid={revision}"}`（逐词不同）或 `{"value": "70dc6b68c855f21e666a7a291ff8ead5ca1f7b44", "url_template": "https://github.com/exam-data/NETEMVocabulary/tree/{revision}"}`（整份文件一个固定修订）。来源 C 可**不声明** → 无链接 | 形状校验：`column`/`value` **互斥且必居其一**；模板必须恰好含**一个** `{revision}`、以 `https://` 开头、无空白/控制字符、≤400 字符；`column` 不得同时出现在 `columns.values()` 里 |
| 映射契约 | `PreviewMapping` 新增 `revision` 字段（**不进 `columns`**，因此不触 `public_lexicon_preview.py:33-34` 的字段白名单）；`preview_file` 把该声明**原样回显**进返回的 `mapping` | 未知键直接拒绝（沿用 `parse_provenance` 的风格，不静默忽略拼写错误） |
| 预览 | 按声明的修订列读**每一行**的单元格，放进 `row["source_revision"]`；修订列在表头缺失 → 现有 `missing_column` 错误 | **fail-closed**：列缺失是错误，**不是**安静的"没有修订" |
| 计划 | 证据项新增 `source_revision`（与 `raw_value` 同级），随 `plan_sha256` 冻结 | 计划是人工审阅物，修订号必须在计划里可见 |
| 确认 | ① `_reverify_sources` 已证明字节与映射未变；② **新增**：按每条证据的 `(source_id, line)` 重读修订并与计划比对，不一致即拒绝；③ `unchanged` 比较**纳入修订**：同键同裁定但修订不同 → 记为 `readjudicated` 并**追加新行**；④ 写入 `source_revision` | 任一不一致 → `ConfirmRefused`，**整体回滚、什么都不写**（沿用现有全有或全无语义） |
| 接口 | 逐字段来源块返回 `source_evidence_id`、`selected_for_default`、`source_revision`，以及**服务端解析好的** `source_revision_url`（空串 = 无法解析） | 解析不出 → 空串，**不返回半个 URL** |
| 界面 | `source_revision_url` 非空才渲染 `<a>`；否则显示来源 + 行号 + 包版本 + 「无法定位到固定修订」 | 见 §4 L3 |

### 3.5 指纹如何验证（四个指纹，各自独立复算）

| 指纹 | 覆盖 | 何时验证 | 失败行为 |
|---|---|---|---|
| `file_sha256` | 来源文件字节 | 预览时计算；**确认时重读重算**（`confirm.py:232-243`） | 拒绝确认 |
| `mapping_sha256` | `columns` + `required_fields` + `encoding` + `delimiter` + **`revision` 声明** | 预览时计算；确认时从重读的文件重构并重算（`confirm.py:244-245`） | 拒绝确认；且映射变 = 找不到旧 artifact = `new` |
| `evidence_sha256` | 文件×映射×**行**×字段×值 | 确认时按 locator 重取值为（`confirm.py:260-283`） | 拒绝确认 |
| **修订重推导（新增）** | 该行修订单元格 | 确认时按 locator 重读并与计划比对 | 拒绝确认 |

`license_text_sha256` 保持"记录、不校验真伪"的既有定位（`joint_preview.py:25-29`）——指纹不能让许可声明为真。

**发布期一次性核验（离线/人工留证，不在渲染路径）**：对来源 B 抽样若干词，按 oldid 取页面
（`…/w/index.php?oldid=<rev>`）核对 `last_editor`/修订时间与钉住清单一致。这条**证明 oldid 指向我们用的那一版**，
是渲染路径之外的证据，结论记入发布记录；未核验时必须留白（见 §5 工作项 9）。

### 3.6 如何防止行号与文件错配（本版新增的硬约束）

1. **渲染路径不读文件、不做行号算术** —— 上一版的"按 `row_locator` 读归档文件"**从渲染路径移除**。
   行号只用于：确认时重推导、界面展示（"第 N 行"）、离线审计。
2. **修订号与证据行同一身份绑定**：修订随 `(file_sha256, mapping_sha256, line, field, raw_value)` 一起被
   `evidence_sha256` 锁定；确认的重推导门保证"同一身份 ⇒ 同一修订"。
3. **同键不同修订不得静默**：显式纳入 `unchanged` 比较，按"重新裁定"**追加**新行（`entry_source_evidence`
   只增不改的既有性质，`confirm.py:615-623`）。
4. **文件换版本 = 新 artifact**：`UNIQUE(file_sha256, mapping_sha256, role)`；旧证据行保留自己的修订，
   历史不能被静默改指向。
5. **映射换声明 = 新 artifact**：`revision` 声明在 `mapping_sha256` 覆盖范围内，改列名或改模板都要重新预览。
6. **表头漂移是错误**：修订列缺失 → `missing_column`（预览期），不产生"空修订"这种无法与真实缺失区分的状态。
7. **单元格为空是合法输入但不可伪造**：例如 `zh_page_exists=no` 的词 → 空修订 → 界面降级；
   空修订**永不**回退成"用行号推一个"。

### 3.7 本机与未来服务器如何复现

| 场景 | 需要什么 | 结果 |
|---|---|---|
| 本机 | `data/vocab.db` 迁移到 `0010`；来源文件**只在预览/确认那一刻**需要在 `--source-root` 内，之后可移走 | `/sources` 与逐词链接完整 |
| 新服务器 | 只带 `data/vocab.db`（或从 `create_backup` 的备份恢复）+ 代码；**不需要** `test-artifacts/`、**不需要** `C:\Temp`、**不需要**任何来源文件 | 逐词链接与来源卡片**逐字段一致** |
| 备份/恢复 | 沿用现有的 `create_backup`（启动时对 `data/vocab.db` 做快照）；新列**随库走**，不新增备份项 | 与方案 B（必须额外备份来源文件）形成对比 |
| 重跑确认 / 复核原文 | 需要 `--source-root` 下那份归档 | 这是 **B8**，此后**只影响复核，不再影响展示** |

## 4. 词条详情中的回查方式

**L1 · 行内**：把现有「来源位置 primary:2」升级为「来源：<来源名> · 第 N 行」+ 内链
`/sources#source-<source_id>`。来源名取自 `source_artifact.publisher`（或 `name`），**不硬编码**。

**L2 · 本词条来源（`<details>`「本词条的来源与修改」）**：逐字段列出

| 列 | 数据来源 |
|---|---|
| 字段（单词/释义/音标/原书原文） | `entry_source_evidence.field_kind` |
| 来源 | `source_artifact.publisher` + `version` |
| 许可 | `license_id` + 静态映射链接 |
| 该字段的来源原文 | `entry_source_evidence.raw_text` |
| 是否被采用 | `decision`/`selected_for_default`/`selection_order` |
| **固定修订** | `entry_source_evidence.source_revision` + 服务端合成的 `source_revision_url` |
| 是否修改 | 措辞级 `provenance_kind` + `derivation_note`；来源级为来源页固定说明 |

**关键规则：显示值旁边的来源，必须来自 `selected_for_default = true` 的证据行。** 证据表对**未采用**的候选
也会留行（`confirm.py:638-670` 为每个字段的每条证据写一行），若不加这条规则，界面可能把一个**我们没用**的
来源标成某个释义的出处。未采用的行只出现在「未采用的其他来源」列表里。

**L3 · 降级（必须实现）**：下列任一情况显示「该词条的来源记录不完整」并写明缺哪一项，**不生成任何链接、
也不静默省略整块**：① 该词条没有任何 `entry_source_evidence` 行（图片导入词、旧数据、或**尚未发生真实导入**）；
② 该字段没有 `selected_for_default` 行；③ `source_revision` 为空；④ 映射未声明 `revision`（来源 C，或声明缺失）；
⑤ `source_revision_url` 为空；⑥ `license_id` 没有静态映射（只显示文本）。

**L4 · 不变量**：`source_raw` 与 `source_meanings` 仍原样展示，「原书原文」区块不变。逐词回查只**加**入口，
不改写、不覆盖、不由 AI 生成任何来源文本。
