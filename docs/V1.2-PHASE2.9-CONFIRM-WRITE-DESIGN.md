## 2. 本切片已交付：只读的锁定计划

### 2.1 产物与入口

```
python -m app.cli public-lexicon plan MANIFEST \
    --source-root DIR --decisions DIR/decisions.json \
    --plan NEW.json --target-lexicon NAME [--require-ready]
```

- `--plan` 用独占创建写出（`open("x")`），**拒绝覆盖**既有计划：计划是证据，不是可重写的中间文件。
- 退出码：写出成功 `0`；生成失败 `2`；加 `--require-ready` 且 `confirmation_ready=False` 时 `1`。
- 来源文件、清单、裁定文件都必须解析到 `--source-root` 内，越界以 `outside_source_root` 拒绝（与既有预览同一信任边界）。

### 2.2 计划结构（决定写入内容的字段）

`rule_versions`、`sources[]`、`joint_report_sha256`、`required_fields`、`target`、`idempotency`、`unmatched_supplement_words`、`entries[]`、`summary`、`confirmation_ready`、`confirmation_blockers`、`plan_sha256`。
另有 `created_utc`、`run_id`、`manifest_file`、`notes` **不参与摘要**（见 §2.5）。

### 2.3 规则版本（写入计划，改变规则即改变计划语义）

| 键 | 值 | 含义 |
|---|---|---|
| `normalization` | `strip_casefold_v1` | 词形身份：仅去首尾空白 + Unicode casefold；内部空格、连字符、撇号、变音符不删 |
| `conflict_detection` | `strip_distinct_v1` | 字段冲突：`strip()` 后按**精确相等**比较，≥2 个不同非空取值即为冲突 |
| `membership` | `primary_source_first_occurrence_v1` | 词条成员与顺序**只来自 primary 来源**；重复词保留首次出现的位置 |
| `single_value_default` | `agreeing_evidence_all_cited_v1` | 唯一取值时默认该值，并引用**所有**给出该取值的证据行，不在地来源之间静默取舍 |
| `source_raw` | `primary_row_raw_line_v1` | `source_raw` = primary 行原始整行，永不改写、永不跨来源拼装 |

### 2.4 人工裁定文件契约

```json
{
  "format_version": 1,
  "decisions": [
    {"normalized_word": "apple", "field": "meaning", "action": "select",
     "evidence": [{"source_id": "primary", "line": 2}], "note": "以主词表释义为默认"},
    {"normalized_word": "bare", "action": "exclude_word", "note": "全部来源缺释义"},
    {"action": "exclude_row", "source_id": "primary", "line": 3, "note": "该行多一列，无法判定字段"}
  ]
}
```

| action | 作用 | 约束 |
|---|---|---|
| `select` | 指定默认展示证据 | 定位必须真实存在且取值非空；`meaning` 可多选并按序，其余单值字段恰好一条 |
| `no_default` | 明确"保留证据但不定默认" | 不得用于 `word`；用于必填字段则该词条保持阻断 |
| `defer` | 明确"尚未裁定" | 使词条阻断并留下可见记录，避免"看起来已裁定" |
| `exclude_word` | 排除整个词条 | 必须写 `note`；不得与逐字段裁定同时出现 |
| `exclude_row` | 承认并排除不可解析行 | 必须写 `note`；该行必须确实是错误行 |

**陈旧的定位是错误，不是空操作**：引用不存在的词、行或字段一律报错并列出全部问题，而不是静默跳过——否则一次笔误会让一个词条"看起来已裁定"而实际未裁定。

### 2.5 幂等契约（确认重试的依据）

计划自身声明它要求确认流程使用的键（`idempotency` 块）：

| 层级 | 键 | 规则 |
|---|---|---|
| run | `plan_sha256` | 相同输入得到相同摘要；重试同一摘要必须返回原结果，不重复写入 |
| source | `source_id` + `role` + `file.sha256` + `mapping_sha256` | 同一文件字节与同一映射再次入库只能报**跳过或冲突** |
| entry | `target.lexicon` + `normalized_word` | 沿用 `uq_lexicon_entry_word` 唯一约束 |
| evidence | `file.sha256` + `mapping_sha256` + `line` + `field` + `raw_value` | **不含 `source_id`**：清单标识不证明来源版本，换标签不能重复入库 |

`plan_sha256` 覆盖决定"会写什么"的字段；`created_utc`、`run_id`、`manifest_file` 在摘要之外——相同输入重复生成得到相同摘要，这正是重复确认幂等的前提。清单文件的字节指纹单独记录，因为清单的语义（每个来源的角色、文件字节、映射）已完整出现在 `sources[]` 里；把它重复计入摘要会让"重排来源顺序"被误判成另一次导入。

### 2.6 阻断规则（`confirmation_blockers`）

| 阻断项 | 触发 |
|---|---|
| `duplicate_source_fingerprint` | 两个来源读同一文件字节且用同一映射（按指纹，不按文件名） |
| `source_file_unusable:<id>` | 来源有文件级问题（编码/表头/空文件）因而产出 0 行 |
| `unacknowledged_bad_rows:<id>` | 有 `csv_error` / `column_count` 行未被 `exclude_row` 承认 |
| `blocked_entries: N` | 存在 `undecided_conflict:*`、`missing_required_field:*`、`no_default_on_required_field:*`、`deferred_decision:*` 的词条 |
| `no_ready_entries` | 没有任何可写入的词条 |

`confirmation_ready` 为真**只表示这份计划自身已裁定完毕**，不构成写入授权。

### 2.7 本切片明确不做

不写 `LexiconEntry` / `UserWordState` / `ReviewEvent`；不打开应用数据库；不做"库内同词"比对（见 §7.1）；不读词频、不产出 `exam_corpus` 角色（`exam_corpus_not_supported`，见 §7.2）；不提供普通用户入口。

## 3. 确认写入设计（**待评审，未实施**）

### 3.1 增量 schema `0008`（提案，须评审后定稿）

新增一张线性 migration `0008_public_lexicon_import.py`，**不改写 `0001`–`0007`**。四张新表，全部以**可空外键**连接既有数据，不回填、不改写 `word`、`user_word_state`、`review_event` 或任何既有 `lexicon_entry` 行。

```sql
CREATE TABLE source_artifact (
    id                    INTEGER PRIMARY KEY,
    role                  VARCHAR(16)  NOT NULL,   -- primary|meaning|phonetic
    name                  VARCHAR(200) NOT NULL,
    publisher             VARCHAR(200) NOT NULL DEFAULT '',
    version               VARCHAR(120) NOT NULL DEFAULT '',
    obtained_at_utc       VARCHAR(40)  NOT NULL,
    format                VARCHAR(32)  NOT NULL,   -- delimited-text-v1
    mapping_json          TEXT         NOT NULL,   -- 冻结的 columns/required/encoding/delimiter
    mapping_sha256        CHAR(64)     NOT NULL,
    file_sha256           CHAR(64)     NOT NULL,
    byte_size             INTEGER      NOT NULL,
    license_id            VARCHAR(80)  NOT NULL,
    license_text_sha256   CHAR(64)     NOT NULL DEFAULT '',
    use_scope             VARCHAR(200) NOT NULL,
    display_scope         VARCHAR(200) NOT NULL,
    storage_locator       VARCHAR(400) NOT NULL,
    created_at            DATETIME     NOT NULL
);
CREATE UNIQUE INDEX uq_source_artifact_identity
    ON source_artifact (file_sha256, mapping_sha256, role);

CREATE TABLE public_import_run (
    id                    INTEGER PRIMARY KEY,
    plan_sha256           CHAR(64)     NOT NULL,
    run_id                VARCHAR(64)  NOT NULL,
    target_lexicon_id     INTEGER      NOT NULL REFERENCES lexicon(id) ON DELETE RESTRICT,
    confirmed_by_user_id  INTEGER      NULL     REFERENCES user(id)    ON DELETE SET NULL,
    confirmed_by_username VARCHAR(64)  NOT NULL DEFAULT '',   -- 不可变快照，见 §3.2
    confirmed_at          DATETIME     NOT NULL,
    status                VARCHAR(16)  NOT NULL,   -- applied|already_applied|refused
    entries_created       INTEGER      NOT NULL DEFAULT 0,
    entries_matched       INTEGER      NOT NULL DEFAULT 0,
    evidence_written      INTEGER      NOT NULL DEFAULT 0,
    result_json           TEXT         NOT NULL DEFAULT '{}',
    error_report_locator  VARCHAR(400) NOT NULL DEFAULT '',
    created_at            DATETIME     NOT NULL
);
CREATE UNIQUE INDEX uq_public_import_run_plan ON public_import_run (plan_sha256);

CREATE TABLE public_import_run_source (
    id                 INTEGER PRIMARY KEY,
    import_run_id      INTEGER NOT NULL REFERENCES public_import_run(id) ON DELETE RESTRICT,
    source_artifact_id INTEGER NOT NULL REFERENCES source_artifact(id)    ON DELETE RESTRICT,
    outcome            VARCHAR(24) NOT NULL,  -- applied|skipped_existing|conflict|refused
    detail             TEXT        NOT NULL DEFAULT ''
);
CREATE UNIQUE INDEX uq_public_import_run_source
    ON public_import_run_source (import_run_id, source_artifact_id);

CREATE TABLE entry_source_evidence (
    id                    INTEGER PRIMARY KEY,
    lexicon_entry_id      INTEGER      NULL REFERENCES lexicon_entry(id) ON DELETE CASCADE,
    source_artifact_id    INTEGER      NOT NULL REFERENCES source_artifact(id) ON DELETE RESTRICT,
    import_run_id         INTEGER      NOT NULL REFERENCES public_import_run(id) ON DELETE RESTRICT,
    normalized_word       VARCHAR(160) NOT NULL,   -- entry 未写入时仍保留词身份
    row_locator           INTEGER      NOT NULL,   -- 源文件物理行号
    field_kind            VARCHAR(24)  NOT NULL,   -- word|meaning|phonetic|part_of_speech
    sense_key             VARCHAR(80)  NOT NULL,   -- 非空；同一行同一字段的稳定义项身份
    raw_word              VARCHAR(160) NOT NULL DEFAULT '',
    raw_text              TEXT         NOT NULL,   -- 原文，逐字保留
    evidence_sha256       CHAR(64)     NOT NULL,   -- 计划里的证据幂等键
    decision              VARCHAR(16)  NOT NULL,   -- selected|not_selected|rejected
    selected_for_default  BOOLEAN      NOT NULL DEFAULT 0,
    selection_order       INTEGER      NULL,
    confirmed_by_username VARCHAR(64)  NOT NULL DEFAULT '',
    confirmed_at          DATETIME     NOT NULL
);
CREATE UNIQUE INDEX uq_entry_source_evidence ON entry_source_evidence (evidence_sha256);
```

**为什么不改 `lexicon_entry` 的现有列**：`source_meanings` / `source_raw` / `phonetic` / `part_of_speech` / `sequence` 继续承载"人工选定的默认展示快照"，多来源证据放新表。给现有词条补一个新的单值来源列，等于把多个来源压进一个装不下它们的形状——这正是总设计 §3.2 与架构 §3.6 拒绝的做法。

**`frequency_*` 保持 `NULL`**：本设计不含频率写入。`exam_frequency_observation` 属 2.9-B，在出现**经核验的纯考研真题语料与统计方法**之前不建表（详见 §7.2）。

### 3.2 确认者的记录方式（一个刻意的取舍）

`confirmed_by_user_id` 用 `ON DELETE SET NULL` 而**不是** `CASCADE`：删除一个管理员账号不该静默抹掉"谁确认过这次导入"的审计。身份由不可变的 `confirmed_by_username` 文本快照保留。这与 `history_event.user_id` 的按用户隔离语义不同——导入运行是**实例级**记录，不是某个用户的学习轨迹。

**待评审**：若评审认为审计必须随账号级联删除，或必须禁止删除有确认记录的管理员，请在此处明确，不要留默认。

### 3.3 管理员确认入口（首版 CLI 两步，沿用既有成例）

```
python -m app.cli public-lexicon confirm --plan PLAN.json --confirm <run_id>
```

与 `history-retention apply --plan --confirm <运行 ID>`（`backend/app/cli.py`）同构：

1. `load_plan` 重算摘要，摘要与文件内容不符即拒绝；
2. 拒绝 `confirmation_ready != true`；
3. 重算每个来源文件的字节 SHA-256 与 `mapping_sha256`，任一与计划不符即拒绝并要求重新预览；
4. 重新读取来源文件，按 `row_locator` 重取原文，逐行核对证据键；
5. 要求管理员输入**自己的用户名与当前口令**（沿用 `app.security` 的口令校验与 `app/services/limiter.py` 的 re-auth 预算），记录 `confirmed_by_username`；
6. 在**单个写事务**内写入 §3.1 各表与新的 `lexicon_entry`，失败整体回滚；事务外写失败报告。

**`--confirm <run_id>` 必须原样输入计划里的运行 ID**：命令永不由定时器或脚本自动触发。若将来提供 API/UI，写接口必须是 `AdminUser` + 本人当前口令复核 + 同源 CSRF 守卫 + `Cache-Control: no-store`，并纳入 `tests/test_authz.py` 的匿名/普通用户/管理员/跨用户矩阵。

### 3.4 事务、写入顺序与幂等

单事务内的顺序（任一步失败整体回滚）：

1. `SELECT` 目标 `Lexicon`（`owner_user_id IS NULL AND visibility='public'`）；不存在或以 `target.lexicon` 不符即拒绝；
2. 按 `uq_public_import_run_plan` 查 `plan_sha256`：已存在且 `status='applied'` → **返回原结果**（`already_applied`），不再写任何行；
3. 对每个来源按 `(file_sha256, mapping_sha256, role)` upsert-or-get `source_artifact`；已存在即记录 `outcome='skipped_existing'`；
4. 对每个 ready 词条按 `(lexicon_id, normalized_word)` 取或建 `lexicon_entry`；已存在则 `entries_matched`，**不覆盖**其现有 `source_meanings`/`source_raw`，而是报告冲突；
5. 按 `evidence_sha256` 插入证据；命中已有唯一键 → 该条记为 `conflict`，不重复插入，也不静默改写；
6. 写 `public_import_run` / `public_import_run_source`，事务提交。

**不得**在这一事务里创建任何 `UserWordState` 或 `ReviewEvent`：领取新词是另一条链路（总设计 §5），确认导入只写内容层。

### 3.5 默认展示快照的写入规则

| 目标列 | 取值 | 溯源 |
|---|---|---|
| `word` | 计划 `default_snapshot.word` | `default_evidence.word` |
| `normalized_word` | `strip_casefold(word)` | 与计划成员规则一致 |
| `phonetic` | `default_snapshot.phonetic`（可为空串） | `default_evidence.phonetic` |
| `part_of_speech` | `default_snapshot.part_of_speech` | `default_evidence.part_of_speech` |
| `source_meanings` | `default_snapshot.source_meanings`（有序） | `default_evidence.meaning` |
| `source_raw` | `default_snapshot.source_raw` = primary 行原始整行 | `default_evidence.source_raw` |
| `sequence` | 计划 `entries[].sequence` | primary 来源顺序 |
| `default_anchor` | **不写**（留空） | AI 生成物，属另一条链路 |
| `frequency_*` | **不写**，保持 `NULL` | 无经核验频率 |
| `lexicon.entry_count` | 见 §4.2 |

每条默认值都能通过 `default_evidence` 回到 `(source_id, line)`。**AI 不参与本设计任何一步。**

### 3.6 失败模式与**挡不住什么**

能挡住：未裁定内容入库、同文件同映射重复入库、静默覆盖既有释义、把多个来源拼成一条"权威释义"、写入用户学习状态、在事务中途失败后留下半成品。

挡不住（必须由人工或后续设计承担）：

- 原始资料的**版权与内容授权**：文件指纹和许可字段只记录声明，不能验证声明为真；
- **释义质量**与词形还原正确性：计划只保证"取的是哪个来源的哪一行原文"；
- **不可信本机并发攻击者**：计划与确认都基于"预览期间来源目录不被其他进程修改"，未提供句柄级绑定；
- **SQLite 单写者资源限制**：一次导入是一个长写事务，期间其他写请求排队；
- 管理员**误裁定**：计划如实记录决定，不判断决定是否合理。

### 3.7 测试策略（Level 1）

先写测试再改语义，覆盖：首次确认零 `UserWordState`/`ReviewEvent`；同 `plan_sha256` 二次确认返回原结果且行数不变；同文件同映射不同 `plan_sha256` 只报 `skipped_existing`/`conflict`；来源文件被改动后旧计划被拒；目标词库不存在/不公开被拒；非管理员与口令错误被拒且无副作用；事务中途失败整体回滚且失败报告落盘；既有 `lexicon_entry` 不被覆盖。新增校验入 `tests/test_authz.py`（若落地 API）。

## 4. 迁移与回滚方案

### 4.1 迁移四闸门（沿用架构 §4.5）

1. **rehearsal**：Level 1 新库 `upgrade 0008` → `downgrade 0007`（仅一次性副本）→ 再 `upgrade 0008`，并跑旧数据兼容测试；Alembic 必须在子进程、显式 `-x db_url=`。
2. **backup**：Level 2 `data/staging/*.db` 用 SQLite online backup API 建真实数据副本；**生产发布窗口另行取得独立 verified backup**。
3. **migration**：对副本执行**显式 revision `0008_...`**，禁止 `upgrade head`。
4. **verification**：逐表行数 + 关键行指纹；`integrity_check=ok`；`foreign_key_check` 0 违规；确认既有 19 条 `lexicon_entry` 等基线不变。

`0008` 是纯增量（四张新表 + 索引），预期既有表零改动；若 verification 发现任何既有行指纹变化，说明 migration 越界，必须停止并排查。

**编号协调（实测风险）**：`PROJECT_STATUS_CURRENT.md:214`（风险 #27）记录 `revoke_reason` 需要 migration `0008` 但"默认不做"；`PROJECT_ROADMAP.md:450`/`:805` 也提到 `0008`。本设计占用 `0008`，须在评审时明确：谁先用 `0008`，另一个顺延为 `0009`。**本设计不修改路线图正文**，只提出这一待决项。

### 4.2 基线影响（**实测发现，必须处理**）

`tools/verified_db.py` 的实测行为：

- **新增行 = `growth`**（`:509-510`），不是失败 → 追加新 `lexicon_entry` **不会**让门禁失败；
- **改动既有行 = `rows_changed` 失败**（`:504-508`）→ 任何对既有行的列写入都会让门禁失败；
- `data/recovery/baseline.json` 的 `lexicon.identity_columns` **包含 `entry_count`**，且 `lexicon` 不在 `IGNORED_COLUMNS` 中。

因此：一次真实导入必然更新公共 `lexicon.entry_count`，**会让 `scripts/check.ps1` 的 verified-backup 一步失败**，直到基线按仓库规则重录。处置顺序（顺序不可颠倒）：

1. 导入发布窗口内先取得**新的 verified backup**；
2. 把 `lexicon.entry_count` 加入 `tools/verified_db.py` 的 `IGNORED_COLUMNS`（这是"代码开始写某列"的既有规则，见 `verified_db.py:133-135` 与 `PROJECT_HANDOFF.md` §"基线冻结"）；
3. 从该新备份重录 `data/recovery/baseline.json`，旧基线归档为 `baseline.prior-attempt-<时间戳>.json`，**绝不覆盖**；
4. 重跑 `scripts/check.ps1` 至 exit 0。

替代方案（更保守）：确认写入**不更新 `entry_count`**，由读取方按 `COUNT(*)` 计算。取舍需评审：前者改动 `IGNORED_COLUMNS`（触及"什么算可信数据"的定义），后者改动既有显示行为。

### 4.3 回滚

- **`0008` 的 downgrade 只允许对一次性副本执行**；生产禁止 downgrade（架构 §4.5）。
- 开发期不迁移、不写生产 `data/vocab.db`（Level 3）。任何恢复先在隔离副本演练，**不能裸拷 WAL 数据库**。
- 导入已发布且已有用户学习记录时**不得删除公共词条**：应停止展示相应证据、停用新领取、修正证据，严重事故走备份恢复流程。
- 证据键 `evidence_sha256` 使"撤销某来源"可定位：撤销许可时停止展示相应证据并重新选择可用默认值，保留依法允许的审计记录，**不能靠覆盖原值假装撤回**。
