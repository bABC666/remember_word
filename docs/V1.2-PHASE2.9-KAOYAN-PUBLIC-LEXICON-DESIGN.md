# V1.2 Phase 2.9 · 考研公共词库与多来源证据技术设计（待审查）

> 状态：设计稿，未获数据源许可确认，未实施。基于 `c1fd11e`（2026-09-24）的代码静态审查。本文的“应”是拟议契约，不表示现有能力。资料名称、版本、授权与可展示范围均**待 dsh 核验**。

## 1. 目标、边界与现状

目标是以经核验的**考研主词表**确定公共词库的词条集合与顺序，以可分别追溯的资料补充释义、音标，并在有可复核真题语料和统计方法时展示**明确口径的考研真题词频**。两名用户共享词条内容，各自领取新词、复习并留存独立进度。云端关闭 OCR 后仍可使用。未经管理员确认的候选不进入公共词库；完整原文不由 AI 改写；不得为缺失词频编数字。

本次只设计，不选择真实资料、不导入生产数据、不改代码或现行路线图。Phase 2.9 可以分验收：**2.9-A 主词表及证据化补充内容**是 Phase 4 上线前置；**2.9-B 真题频率**只有在真题来源、使用许可、覆盖范围和方法均核验后才能宣称完成。若频率资料未就绪，界面不显示排名或零频，也不能宣称达成新的完整产品目标。

## 2. 方案比较与选择

| 方案 | 优点 | 不足 | 裁定 |
|---|---|---|---|
| 仅用现有 `LexiconEntry` 字段，证据放外部 JSON | 无 migration，最快交付 | 补充源混入单组字段后无法逐字段查询许可/原文；数据库恢复与证据易失配；单值频率无英语一/二、年份或方法口径 | 不用于多来源正式交付；可作不发布的解析试验 |
| 每个来源建一份公共 `Lexicon` | 模型改动少，来源天然分开 | 同词身份分裂，用户状态不再共享；跨库去重和合成展示困难 | 不选 |
| **一个考研主词库 + 附加来源证据表** | 词条身份稳定、个人进度不变；可按字段和许可展示；真题统计有独立口径 | 需要新的增量 migration、预览及发布门禁 | **推荐** |

管理入口首版采用**管理员 CLI 两步命令**（`preview`、`confirm --plan-sha256 ...`）。它在服务器本地处理大文件，避免未审查的浏览器上传格式和 UI；确认必须验证管理员本人身份与当前口令，并记录确认者，不能只凭操作系统用户名。CLI 只调用与未来受保护 API 共用的预览/确认服务。若后续提供 API/UI，写接口须 `AdminUser`、本人当前口令复核、同源 CSRF 守卫及 `no-store`；普通用户不可访问预览文件或原始许可受限材料。现有 `POST /api/imports` 保持图片私有流程。

## 3. 来源分层与字段契约

### 3.1 三类输入

1. **主词表**决定 `LexiconEntry` 成员、规范词形和 `sequence`。只有此类来源可新增公共词条。词表自带释义/音标可作为各自证据，但“主词表”身份不自动授予补充资料的展示权。
2. **释义/音标来源**只为已匹配的主词条提供独立证据。未匹配项进入报告，不因补充源而新增词条。多个来源的义项保持分组与原文，不自动拼接成一个无来源的“权威释义”。
3. **真题频率来源**须能证明题目文本与使用范围；其统计结果与词条内容分开。普通综合英语语料只能标为“综合语料”，不可标作“考研真题”。词频资料也不能替代主词表。

每份原始文件在预览清单和正式入库中记录：来源名称、发布者、版本/发布日期、取得时间、原始字节 SHA-256 与大小、格式、许可名称/文本或许可文件指纹、允许的存储/加工/对用户展示范围、保留位置、字段映射版本及其 SHA-256。所有这些事实先标“待 dsh 核验”；无明确许可或无法核对原始文件时，预览可以做本地评估，**不得确认发布**。原文件放受控存储，数据库保存不可变指纹和定位信息；授权不允许分发原文件时仅在授权范围内向用户展示派生字段，管理员仍须能核对原文。许可冲突不通过合并字段消失。

### 3.2 建议的增量 schema（须在实施设计复核后定稿）

| 对象 | 最小字段及约束 | 用途 |
|---|---|---|
| `source_artifact` | `id`、`role`（primary/meaning/phonetic/exam_corpus）、`name`、`publisher`、`version`、`license_id`、`license_text_sha256`、`use_scope`、`display_scope`、`file_sha256`、`byte_size`、`format`、`storage_locator`、`mapping_sha256`、`created_at`；版本/指纹不可原地修改 | 每份材料的来源与许可证据；文件指纹用于识别重复文件，不用文件名识别 |
| `entry_source_evidence` | `id`、`lexicon_entry_id`、`source_artifact_id`、`row_locator`、`field_kind`、`raw_word`、`raw_text`、`parsed_value_json`、非空 `sense_key`、`decision`、`selected_for_default`、`selection_order`、`confirmed_by_user_id`、`confirmed_at`；唯一键覆盖同文件同位置同字段同义项 | 逐字段原文及人工采纳/拒绝记录；旧版本证据保留，当前展示按已确认且许可允许的证据选取；单值默认字段最多一条生效证据，释义可按序选多条 |
| `exam_frequency_observation` | `entry_id`、`source_artifact_id`、`exam_track`（英语一/英语二）、`year_from/to`、`occurrence_count`、`paper_count`、`token_denominator`、`rank`、`count_unit`、`normalization_method_sha256`、`corpus_coverage_json`、`confirmed_by/at`；同来源/词条/轨道/时期/方法唯一 | 保存一个**有作用域**的统计观察，禁止将不兼容口径的数字压进单值 `frequency_rank` |
| `public_import_run` | `plan_sha256` 唯一、输入文件/映射指纹集合、目标词库、预览摘要、管理员、状态、确认时间、前后行数/关键指纹、错误报告定位 | 事务与重复确认的幂等键；便于部署和审计 |

这些是设计字段，不是本次 migration。`LexiconEntry.source_meanings/source_raw/phonetic` 继续承载**人工选定的默认展示快照**；每个快照的证据引用必须可追踪，补充来源的其他义项通过来源分组展示。建议在 `entry_source_evidence` 的决定记录中注明是否选为默认值；更换默认值要新确认并保留旧证据，不能因新文件出现而静默覆盖。AI 只可产生候选 anchor/解释，不得成为原文、许可或频率证据。`frequency_*` 旧列首版保持 `NULL`，直到有一个明确作用域的消费契约；不得把“英语一某几年”伪装成全考研单值。

新表以可空外键连接既有数据，不回填/改写旧 `word`、旧图片批次或个人状态。若 dsh 最终只准单一来源且无真题频率，仍可做缩减版零 schema 导入，但它不能满足本设计的多来源可分辨目标，必须重新评审和标明降级范围。

## 4. 规范化、冲突、版本与确认流程

**词条身份**沿用同一公共 `Lexicon` 内的 `normalized_word` 唯一约束。默认仅去首尾空白并做 Unicode casefold；内部空格、连字符、撇号和变音符不擅自删除。词形还原（复数、时态、派生）是带方法版本的候选匹配：先精确规范词形，后用经核验的显式词形映射；多候选、专有词/普通词冲突或义项不兼容均待人工裁定，不能由 AI 猜一个 lemma 后直接入库。一个主词条若含多义项，应保留原顺序、编号、词性和原文定位；不同来源同词的义项分别保留，不按中文文本相似度自动合并。

**预览**读取原始字节，锁定文件、映射规则和规范化方法的指纹，生成不可变计划与逐行报告。报告至少列：总行、有效/缺字段/错误行、主词表新增、文件内重复、库内同词、跨来源匹配/未匹配、义项冲突、词形还原不确定、许可不可展示、频率缺口及样例。预览不写正式词库；错误行带文件定位和原因。不同文件的来源原文不得互相覆盖。

**确认**重新计算所有输入指纹与计划 SHA-256，并在写事务内核对预览时目标词库的条目/证据指纹；确认者看到计划摘要、冲突清单和被排除行。任一文件、规则或目标内容变化即拒绝旧计划并要求重新预览。未裁定的内容冲突、许可缺口、主词表身份冲突默认阻断；管理员可明确排除错误行，不能以“尽量导入”静默跳过。一次确认在单个数据库事务内写 `public_import_run`、来源、证据与词条，失败整体回滚，并在事务外保存失败报告。确认前不产生 `LexiconEntry`、`UserWordState`、`ReviewEvent`。同一 `plan_sha256` 重试返回原结果；即使新计划 SHA 不同，已入库的同一文件指纹、映射和来源版本也只能报告跳过/冲突，不能再添加相同证据。同文件不同映射或新版必须新预览。数据库唯一约束是并发兜底，不代替冲突报告。

**版本升级**视为新 `source_artifact` 和新计划。已有 `LexiconEntry.id` 保持稳定；新增词可追加，原列表中删去的词只报告“候选退场”，不自动删条目或学习记录。默认值变化逐字段列出旧值、新值及证据，需管理员另行确认。若撤销某许可，停止展示相应证据并重新选择可用默认值；保留依法允许的审计记录，具体删除/隔离按许可证和数据治理决定，不能靠覆盖原值假装撤回。

## 5. 公共词如何进入今日学习

| 策略 | 优点 | 风险 | 结论 |
|---|---|---|---|
| 用户逐词点“加入学习” | 意图明确，状态仅按需创建 | 大词表逐个操作成本高；每天新词目标仍需用户手工凑齐 | 可作为以后补充动作，不作为首版主路径 |
| **按每日额度显式领取** | 与现有今日队列、每日目标吻合；一次领取少量状态 | 必须防刷新/并发重复领取及“领取未复习”额度穿透 | **首版采用** |

`POST /api/study/claim-new`（拟议）是唯一公共词库批量入计划动作；`GET /api/study/today` 继续只读。调用者只能为自己从已启用公共词库领取，服务端按主词表 `sequence` 再稳定 `entry.id` 选词；权限和归属只来自会话。创建 `UserWordState` 的时点是**领取事务成功**，不在文件导入、公共词库启用、预览或只读列表时。`(user_id, lexicon_entry_id)` 唯一键和单写者事务保证并发/重试不会生成重复状态；返回实际新建的 state id 与已存在数。不得创建复习事件，首次真实评分才写 `ReviewEvent`。

额度规则应以 UTC 日计算，保留“到期复习先于新词”：全局及各词库可领取数 = 配额减去**当天已首次复习的新词与当前所有未复习的 `new` 状态的去重并集**；领取后未评分词先作为待学积压，次日仍占新词空间，避免每天再领一批。这里既有 `review_event.status_before='new'` 与 `UserWordState.status='new'` 需要按词条 ID 做集合并集，不能简单相加，也不能只看当前请求数。私有导入已创建的待学状态同样占全局队列空间；现有 `daily_new_words.consumed_today` 可继续表示实际首次评分，新增“待学数/可领取数”供界面说明，避免把领取数冒充已学数。需专门回归今天、跨天、并发和跨词库两层额度。

`UserLexicon.enabled=False` 的拟议语义是停止该词库的新领取并从今日队列暂时隐藏其待学和到期项，但**不删除状态、事件或排期**；词条详情与历史仍可读，重新启用后原状态原样返回。当前代码未过滤 `enabled`，实施时须显式修改队列与测试，界面须提示可能暂停到期复习。若产品希望停用后仍复习旧词，应在实施前将此处改成“只阻止新领取”；不能让 API 与界面各自猜测。

## 6. 真题频率的可展示条件

一条统计必须说明：语料究竟是**纯考研真题**还是混合语料；英语一、英语二分别统计，混合值只在两者覆盖完整且方法一致时另算并标注；覆盖年份和实际纳入的试卷/题型；是否剔除重复试题、答案、说明文字；计数单位是原词形 token、归并 lemma 的出现次数还是“出现过的试卷数”；分词、大小写、词形还原、多词短语、同分排名方法及方法版本；语料分母和缺年情况。`occurrence_count=0` 仅在已完整扫描所声明范围且确证未出现时成立；未覆盖或无法匹配为 `NULL/无可靠数据`，不冒充零。

默认推荐展示“英语一/二 · 年份范围 · 出现次数（定义）· 已扫描试卷数/总 token 分母 · 来源”。若统计选择 lemma 归并，须公开词形映射表和例外；出现次数按每份试卷去重后的指定题目正文 token 计，另存“出现过的试卷数”，两者不能混称。排名只在同范围全词表、同方法、同分规则确定后展示；建议以次数降序、并列为竞赛排名（如 1、1、3），词形仅用于稳定显示次序。若只有第三方排行榜而无可复核语料和方法，可存为未核验候选，**不展示精确计数或排序**。综合语料只能独立标注，不与真题次数相加。频率的用户可见范围还受源文件许可约束。词频排序影响选新词属于独立消费者改动，不能改既有状态或到期时间；无可靠证据时回退主词表顺序，而不是 `frequency_rank` 猜值。

## 7. 安全、失败边界与回滚

CLI 预览只读源文件及测试/隔离数据库；管理员确认前先核对身份、口令、计划和许可证，不写正式内容。预览和报告需限制大小与行数、只接受经设计批准的格式、拒绝路径逃逸/压缩炸弹和不可信公式执行；不得在错误日志中打印口令或受限原文。确认报告只暴露管理员允许看的来源信息。普通用户对公共内容只有读取与各自 `UserLexicon`/学习状态写入能力。新 API 如落地，加入 `test_authz.py` 的匿名、普通用户、管理员、跨用户矩阵。

本设计能避免**未确认内容入库、同文件重复、静默覆盖与用户状态交叉写入**；它不能替代对原始资料版权、真题语料真实性、释义质量或词形还原正确性的人工核验，也不能消除 SQLite 单写者资源限制。许可撤回、错误发布和来源纠错必须有明确操作人及新报告。

迁移如采用 §3.2，新增线性 `0008_*`，不改写 0001–0007；先在 Level 1 新库做 upgrade/downgrade 与旧数据兼容测试，再用 SQLite online backup API 建 Level 2 副本，执行**显式 revision** 的 `rehearsal → backup → migration → verification`：逐表行数、关键行指纹、外键与完整性，确认旧 19 条等基线不变。生产发布窗口先取得独立 verified backup，再迁移；**生产禁止 downgrade**。尚未对外发布的新导入失败可在事务回滚；已发布且已有学习记录时不得删公共词条，应撤销展示/停用新领取、修正证据并由备份恢复流程处理严重事故。任何恢复先在隔离副本演练，不能裸拷 WAL 数据库。
