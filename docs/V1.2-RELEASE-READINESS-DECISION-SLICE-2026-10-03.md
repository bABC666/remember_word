## 3. 首发建议内容边界与必须显示的信息

**技术建议，待许可与负责人决定后才能成为发布范围**：默认库先限定为 NETEM 的 5528 个规范化词头和原顺序；不导入 NETEM 原始释义、其他拼写或混合语料计数。仅把已固定修订、已核对许可链的 zh.wiktionary 内容及已核对包版本的 WikDict 内容作为**来源原文／证据**；两源非空时可有明确字段选择，但“原文默认值”不等于已确认短义。**早期全量导入预演**只对冻结 300 词选择默认来源原文：282 词选 zh、17 词选 WikDict、1 词空；当时其余 5228 词的默认来源原文字段仍空。**后续前 1000 词预演**已在新隔离库确认 880 词、993 条按词性短义（见 `docs/V1.2-PHASE2.9-TOP1000-POS-ADJUDICATION.md`）；这不是前述 300 词原文字段选择的统计，也不是生产导入或许可核准。只有证据链确认且通过展示门禁的 `concise_meanings` 才显示为“核心释义”；不凭空编写、复制 NETEM 短释义或把未经核对的来源值伪装成已确认短义。来源原文如展示，应与核心释义分区并明示来源与未确认状态；释义为空的词可以保留在收词表里。排名 1000 之后尚未批量确认短义，隔离结果**不等于**首发已具质量覆盖率。

应用内“数据来源与许可”页、词条来源入口已存在，但首发仍必须让实际展示内容关联到：NETEM 项目／作者贡献者、固定版本、CC BY-NC-SA 4.0 链接与字段规范化／删列说明；zh.wiktionary 各词固定修订链接（可达页面历史／贡献者）、适用许可链接、清洗及繁简修改说明，并保留额外上游署名；WikDict／Karl Bartel、DBnary／Wiktionary 上游链、包版本、CC BY-SA 4.0 链接与抽取修改说明。许可声明应与“已获批准”状态分开显示；不得把“不提供下载”说成许可限制。两种 SA 与 NETEM NC 对组合及服务范围的适用，须有明确决定后才写正式对外许可表述。

## 4. 进入“生产副本迁移及导入预演”前的条件

1. **许可／负责人闸门**：逐来源签定真实服务用途的 `use_scope`、`display_scope`、署名、修改说明和许可标识；NETEM NC、各源 SA／组合方式、zh.wiktionary 旧修订与 CC-CEDICT、WikDict／DBnary 链获得负责人与必要法律意见。现有“预演草案·未获批准”只能用于只读预演，不能换名当正式批准。
2. **输入闸门**：正式来源清单可机读 provenance 与固定版本／文件 SHA-256／映射 SHA-256 完整闭合，zh 逐词 `oldid` 可回查；NETEM 映射只收词与顺序并机械排除原始 `释义`，不把来源自述词频误标真题词频；按导入器 `strip().casefold()` 规则重算收词、重复和覆盖数字，不沿用旧研究的另一种规范化统计作验收数。
3. **质量与展示闸门**：先确定首发允许多少词仅有词头、多少词可见来源原文；按证据链与展示门禁复核前 1000 词隔离短义，解决歧义、缺义和上游隔离项，并检查来源页、修订链接、许可链接、署名与修改标记能对实际数据工作。不得把早期 300 词原文字段选择当作短义确认，也不得把后续 880 词、993 条隔离确认当作排名 1000 之后的覆盖率。
4. **副本预演闸门**：在上述清单和锁定计划获准后，用 SQLite online backup API 从生产库取**独立副本**（避免遗漏活动 WAL），记录生产与副本指纹及当前 revision；先做只读 `preflight-target` 并人工审阅同词冲突和 provenance 差异，再按明确版本对副本做迁移与导入预演，核对既有行、完整性、外键、来源证据和双用户行为。旧的 0007→0008 生产副本测试只证明当时的 schema 安全，不证明当前 head 或真实来源导入已通过。生产主库保持不动；本报告完成后停止。
