## 决策：确认前的可机检条件

1. **主引用**：非 `ai_supplement` 必须解析出已声明的来源、固定版本与位置，并绑定到同词条、同来源、同版本、同字段的持久证据。对 WikDict，位置是 CSV 物理行，须与证据行的 `source_artifact_id`、`row_locator`、`field_kind=meaning`、`raw_text` 一致。对 zh.wiktionary，`oldid:行` 必须绑定到该 oldid 的**原文行**，且引用行含支撑拟议文字的可核对片段；不能只拿汇总 CSV 的证据 ID 代替。`derived` 另需具体改写说明；`source` 的逐字断言须对准所引行，而非同词任意汇总文本。
2. **附加引用**：逐条应用与主引用相同的来源、版本、位置、词条、原文匹配规则；`citation_order` 唯一。一个释义可有不同来源的证据行，多个释义也可共用一行。`ai_supplement` 的主引用与附加引用均须为空。引用的数据库 ID 不能从定位串推导，也不能只验“属于同一词条”。
3. **`pos_section`**：`pos_evidence_locator` 必须解析为同一固定原文中的标题行；该行文本须在词性标题闭集并映射到 `pos_key`；拟议释义行须位于它统辖的**目标语言**小节内。`發音`、`詞源` 等非词性标题一律不通过。`reviewer` 可记录人工试判，但须有命名确认人及可核对的目标语言释义行，不得在界面上伪装为来源词性。
4. **语言归属**：由固定原文的语言标题和行所处的小节路径判定，而不是接受提案填写的 `language='en'`。WikDict 如无逐行语言小节，只能依据已绑定的来源级语言声明确认其文字所属语言；它仍不能证明逐义词性。跨语言行、无语言路径或版本不明的行不得确认成英语来源义。

**现有能力与缺口。** 当前 schema 能限制词性键、`pos_source`、语言枚举、非空位置、每组位次，以及引用证据 ID 的外键；服务还核对证据 ID 属于同一词条。`entry_source_evidence` 可留存转换文件的来源工件、CSV 行号、整格原文和（有声明时的）修订号。它没有 wikitext 逐行原文、标题层级、该行语言路径及其与汇总 CSV 单格的持久映射；提案也没有词性标题证据 ID。位置串与证据 ID 的版本/行/原文一致性尚未校验。文件系统中的保全 JSON 与抽取索引可供本次离线核对，但不能由现有数据库证据 ID 独立证明这些逐行关系。

**拒绝规则。** 确认时只要任何必需绑定缺失、版本/行/原文不一致、标题不是对应词性、语言不是目标语言，或只能得到汇总 CSV 而无法证明拟议 wikitext 行，就拒绝该来源支持的确认，并指出失败的定位串和缺失证据。不得把 `pos_section` 自动降为 `reviewer`、把跨语言行改标 `en`、从 `zh_oldid` 猜补证据行，或把无来源义改称引文。无来源内容仅可另作显式 `ai_supplement` 候选，走独立人工确认与展示标签；`fertiliser` 当前仍停在候选。

**最小后续实现范围（本片不执行）。** 先确定定位串别名和版本规则；为固定 wikitext 的被引释义行与标题行增加不可变的逐行证据（含工件指纹、oldid、行号、原文、语言/标题路径），或等价的可持久回查索引；给主引用、附加引用和词性依据建立到相应证据的绑定；在唯一确认入口集中校验上述条件并覆盖四个样本的拒绝/通过情形。WikDict 复用已有 CSV 证据行并明确其包版本，不推断逐义词性。正式来源清单的修订声明与任何真实数据回填另行处理；此记录不修改它们。
