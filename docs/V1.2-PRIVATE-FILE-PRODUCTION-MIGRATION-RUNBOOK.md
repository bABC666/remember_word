先由负责人安排停机窗口并告知使用者停止所有写入。**此步只在获得生产放行后执行；不要在预审时运行。**

```powershell
.\scripts\stop-vocab.ps1
if ($LASTEXITCODE -ne 0) { throw '停机失败' }
if (Get-NetTCPConnection -LocalPort 8000 -State Listen -ErrorAction SilentlyContinue) { throw '8000 仍有监听' }
.\scripts\stop-vocab.ps1 -Status
# 核对输出中的项目 Python 进程、pid 与监听均已消失；另外排查任务计划器或其他连接该库的写入者。
$samples = 1..5 | ForEach-Object {
  $wal = "$db-wal"
  [pscustomobject]@{
    db = (Get-FileHash -LiteralPath $db -Algorithm SHA256).Hash
    wal = if (Test-Path -LiteralPath $wal) { (Get-FileHash -LiteralPath $wal -Algorithm SHA256).Hash } else { '<absent>' }
    walBytes = if (Test-Path -LiteralPath $wal) { (Get-Item -LiteralPath $wal).Length } else { 0 }
```

## B. 当次基线、预演和备份

所有 JSON 只含列名、行数、指纹与检查结果，仍置于受保护的 `data/recovery/`；数据库副本与备份含生产信息，保留在受保护的本地 `data/`，不得提交或外传。`snapshot`/`compare` 只读；`backup` 从 `mode=ro` 源使用 SQLite online backup API 创建**新文件**，拒绝覆盖。命令退出非零即停止，不继续下一步。

## C. 显式迁移和逐步核验

再次确认服务无监听、没有写入者，且 `compare` 在生产库上仍为 `0007` 和基线一致。此时才运行下面的**生产写入**命令；本执行包编写与副本检查期间不得运行。

```powershell

if ($LASTEXITCODE -ne 0) { throw '生产库已变化' }
Push-Location backend
```

## D. 启动、冒烟、失败恢复

只有 C 全部通过，才运行 `scripts/start-vocab.ps1`；确认 `prepare-database.ps1` 返回 `current`、没有迁移，健康检查 200。使用正式用户经浏览器做 TXT 与 CSV 预览（预览不新增词库）、确认导入、选择新私有词库、学习一次、重启后保持选择；同时核对原有词库和历史仍可见、私有词库只对本人可见。测试会写入生产业务数据，须在发布放行和安排好的冒烟账号范围内进行，并记录词库 ID、时间、结果。若没有获批的生产冒烟账号/数据，停止在启动前，不用真实用户数据临时代替。

失败恢复只从当次 `$backup` 开始。先确保服务和全部写入者再次静止，保存失败库及 `-wal`/`-shm` 到受保护恢复目录供调查；校验备份 SHA-256 与记录相同，恢复前确认是否已有迁移后新写入（恢复会丢弃这段写入，必须另行处理）。将备份复制回固定的 `data/vocab.db`，确保旧 WAL/SHM 不会叠加到恢复库；运行 `snapshot`/`compare` 验证 `0007`、完整性、外键和原数据指纹。**代码必须切回 `$oldCodeSha` 对应的 `0007` 版本**（已验证该提交仅包含至 `0007`），先用该版本的启动前检查确认 `current`，再启动。当前 `0014` 代码不能直接服务恢复后的 `0007` 库。恢复步骤涉及生产文件替换，须由负责人在失败现场批准具体操作与新写入取舍，不能把直接 `downgrade` 当恢复方案。
