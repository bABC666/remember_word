# Phase 2.9：目标公共词库只读预检切片记录

基线为本地审查合流 `a29e231`；独立分支 `codex/phase29-target-readonly-preflight`。本切片没有合并、推送、启动正式实例，也没有打开或迁移主工作区的生产 `data/vocab.db`。

## 行为与边界

命令：`python -m app.cli public-lexicon preflight-target --plan PLAN.json --source-root SOURCES --database COPY.db`。数据库路径必须显式给出；SQLite 用 `mode=ro` 打开（**并且在没有活动 `-wal` 时加 `immutable=1`，见下**），并设置 `query_only=ON`。命令只向标准输出打印 JSON，不生成报告文件、不初始化应用数据库、不写入任何表。

报告核对锁定计划摘要及来源文件的字节与映射指纹，指出目标名称对应的系统公共词库是否唯一存在；按 `(lexicon_id, normalized_word)` 对比已有词条，将词形、音标、词性、释义数组、原始行及顺序的库内值和计划值逐字段列出。每个来源报告文件与映射 SHA-256、声明的发布者/版本/取得时间/许可/使用和展示范围，以及与相同 `(file_sha256, mapping_sha256, role)` 的既有 `source_artifact` 的逐字段差异。沿用确认写入对归档声明的比较口径；冲突阻断技术确认。报告另含 `read_mode`，说明目标是以哪种方式打开的。

`counts` 的 `new`、`matched` 是当前条件下预计的确认结果；`blocked` 含计划本来阻断的词及因缺目标、来源变化或声明冲突而不能确认的 ready 词；`excluded` 单列人工排除项。**相同摘要且同一目标词库**已有 `public_import_run` 时报告 `prior_run`，预计新增和匹配均为零；若该运行属于**另一个** `target_lexicon_id`（词库改名后新词库沿用旧名），另记 `prior_run_other_target` 并加 `prior_run_target_mismatch` 阻断——确认在这种情况下会对另一个词库的记录回答"已完成"，预检必须把这件事说出来而不是显示空差异。库内同词始终只报告差异，确认写入仍须在事务中重新检查，预检不预留行。

`technical_preflight_passed` 只表示当前机器预检没有发现阻断；**不代表来源许可真实、使用范围已获授权，也不代替人工释义裁定或管理员确认**。报告第一项 `authorization_review` 对普通声明固定为 `not_assessed`。如果来源自身明确标注“未获批准”（包括预演草案），标为 `pending_owner_approval`，列出来源并写明“仍待负责人批准”，计入阻断并以非零退出。此识别只忠实呈现提交者的明确声明，机器既不授予也不判断法律授权；它是一个**固定的关键词表**（大小写与连字符不敏感），只能作为信号，报告在任何情况下都声明未核实授权。实际确认仍按现有口令复核和单事务写入路径执行。

## 只读的准确含义（2026-09-26 联合评审修正）

`mode=ro` **本身不足以**称为"不在目标旁边写任何东西"。应用连接过每个数据库（`app/db.py` 在 connect 时设 `journal_mode=WAL`），而 SQLite 以 `mode=ro` 打开这样的文件时仍会在同目录创建 `-shm`（wal-index，32 KiB）与 `-wal`：这在只读介质上直接失败，也让"同目录 SQLite 文件哈希保持不变"的说法不成立。实测（用与预检完全相同的连接串）：非 WAL 目标前后 `['plain.db']` 不变；WAL 目标由 `['target.db']` 变为 `['target.db', 'target.db-shm', 'target.db-wal']`。

因此改为：目标旁边**没有活动 `-wal`**（不存在或大小为 0）时用 `mode=ro&immutable=1`，不创建任何文件；**存在活动 `-wal`** 时保留 `mode=ro` 并如实报告 `read_mode="read_only_with_live_wal"`。不用 `immutable=1` 覆盖后一种情况，是因为它会**静默忽略 `-wal`**：实测同一个带活动 WAL 的副本，`immutable=1` 读到 1 行而 `mode=ro` 读到 2 行——落后代码的数据库会被比成最新，比多两个文件严重得多。

## 真实来源副本预演尚缺

需要对真实来源文件的清单补齐可机读 `provenance`，并由负责人逐项核实发布者、版本、许可文本指纹和允许的存储/加工/展示范围；既有真实来源预演清单没有该块。需要针对同一批真实来源重新生成人工裁定的锁定计划，再在**单独的真实生产库副本**上运行本预检，人工审阅库内同词内容差异及来源声明差异。其后如要做确认导入与双用户验收，仍须独立批准并在副本上执行；本记录的机器报告不授予许可或释义裁定。
