## 3. 验收发现的唯一偏差（F-DOD4-1，已决定：保留原生校验）

改密表单的"新密码过短"分支（组件里的 `新密码至少 8 位。`）**在真实浏览器里永远不会执行**：输入框带 `minLength={8}`，Chrome 在提交阶段就拦下了（`validationMessage="请将该文本增加为 8 个字符或更多（您当前使用的是 7 个字符）。"`），React 的 `onSubmit` 根本没跑。jsdom 测试不实现原生约束校验，所以 `frontend/src/security.test.tsx` 里那条断言在真实浏览器中对应的是**另一个提示**。

- 影响：**无安全影响**——口令没有被发出（本步 `/api/auth/password` 调用 0 次），服务端另有自己的长度规则，用户也被告知原因。
- **决定（2026-09-24，Batch 12）：保留 Chrome 原生 `minLength` 校验**，不改表单行为、不削弱任何断言；只修正 jsdom 测试的名称与说明（`frontend/src/security.test.tsx`），明确指出 `新密码至少 8 位。` 这条 React 分支**不是当前真实浏览器里可见的提示**（真实浏览器显示原生提示），它只是 jsdom 下的回归守卫。

## 5. 复现方式

1. 建副本：`tools/staging_three_user_check.py` 的 `online_backup()`（online backup API + `journal_mode=delete` + 拒绝覆盖）。
2. 建 staging 账号：`python -m tools.staging_accounts create-user <name> --role user`，口令经 stdin（环境 `VOCAB_DATA_DIR`/`VOCAB_DATABASE_PATH` 指向副本）。
3. 起实例：`uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port <独立端口>`，环境同上；本批另设 `VOCAB_REAUTH_FAILURES=3`、`VOCAB_REAUTH_WINDOW_SECONDS=45`（默认 5 / 300，见 §6）。
4. 跑驱动：`node driver.cjs`（`test-artifacts/dod4-browser-20260923T162528Z/driver.cjs`），口令经环境变量传入。
5. 收尾：停止实例、复核生产库三文件指纹、扫描产物无口令。

`test-artifacts/dod4-browser-20260923T162528Z/acceptance-orchestrator.py` 是本次编排脚本（含副本创建、账号创建、实例启停、证据与报告生成），与本文件一并作为方法证据保留。

## 6. 偏差与限制（如实记录）

1. **二次认证预算用非默认值**（3 次 / 45 秒而非 5 次 / 300 秒），否则一次验收内无法到达 429 与等待结束；默认值由后端契约测试覆盖。
2. **浏览器为 headless Chrome**（真实引擎、真实网络栈、真实 cookie jar，但不显示窗口）。
3. **"其他设备"由 API 创建**（一个浏览器即一台设备）；被验收的是**浏览器里的撤销动作本身**。
4. **截图供人复核**：本批的 agent 无法读取图像，因此所有机读结论都来自同一时刻的 DOM 断言与网络日志，不依赖"看图"。
5. **S-1 未做浏览器验收**：前端无入口，按 §4 第 2 条处理。
6. 本次验收**不改代码、不改版本号、不打 tag、不 push、不重启活实例、不执行 G6 生产清理**。
7. **Batch 12 只改文档与测试说明**：`frontend/src/security.test.tsx` 的测试名称/注释（断言不变、表单行为不变），以及本文件与三份规划文档的口径收口；未改三处版本号、未打 tag、未重启活实例、未执行 G6 生产清理。
8. **`-shm` 是 WAL 索引，会随只读 attach 改写**：它不是数据。因此"生产库未变"的正确判据是 `vocab.db` + `-wal` 两个文件的 sha256，再加一次 `integrity_check` / `foreign_key_check`；只读地把库打开一次也可能让 `-shm` 的字节变化（同一机制在 T14 的处置记录 `data/recovery/t14-staging-disposal-20260923T155046Z.json` 里也有记载）。
