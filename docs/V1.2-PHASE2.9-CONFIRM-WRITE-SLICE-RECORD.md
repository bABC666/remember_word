## 2. 契约（都有测试固定）

| 契约 | 行为 |
|---|---|
| 重试幂等 | 同一 `plan_sha256` 再次确认 → 返回 `already_applied` 与原结果，**不写任何新内容**；该判断在重新读取来源文件**之前**，所以文件事后被改动/删除也不影响重试结果。**前提是目标词库相同**：摘要冻结的是目标词库的**名字**而不是 id，因此若记录的运行指向另一个 `target_lexicon_id`，拒绝而不是回答"已完成"（见 §10.2 D3） |
| 同文件同映射 | 已入库的证据不再重复写入；`source_artifact` 按 `(file_sha256, mapping_sha256, role)` 复用，不按文件名重复建档 |
| 库内同词 | 目标库已有同 `normalized_word` → 记为 `already_in_lexicon` 冲突、计入 `entries_matched`，**既有行一个字段都不改**；且不为它写证据（没有发生采纳） |
| 文件变化拒绝 | 重新读取每个来源，比对字节 SHA-256 与映射指纹，再按 `(line, field)` 逐条比对计划里的原值；任一不符 → 拒绝，不"适应"新内容 |
| **写入值必须能由计划自己的证据推出** | 除上面的引文比对外，**将要写入的值**也重新推导：`source_meanings` 必须等于计划声明选中的证据值（按序、去重），`source_raw` 必须等于主来源行的原样整行，`word`/`phonetic`/`part_of_speech` 必须是声明选中的值之一；不符 → 拒绝整次确认（见 §10.2 D1） |
| 计划完整性 | 摘要不符（被编辑过）或 `confirmation_ready` 非真 → 拒绝。**摘要只发现误改，不是签名**：谁改计划都能重算它，因此授权元数据与写入值都另有一层重推 |
| 权限 | 非管理员 / 已停用账号 → 拒绝；CLI 还要求管理员**本人当前口令**（`getpass`，绝不进 argv） |
| 事务原子性 | 写事务中途失败 → **整体回滚**；失败报告在事务外写入，独占创建、不覆盖既有报告 |
| 不可变历史 | 确认路径**不发出任何 `UPDATE`/`DELETE`**——包括运行行本身：`public_import_run` 的计数在**插入之前**就已决定，因此这一行也是完整插入一次，不存在"先插入再改计数"（见 §10.2 D2）；重新裁定追加新行 |
| 不写学习状态 | 不创建 `UserWordState`、不创建 `ReviewEvent` |
| 不写缓存列 | 不更新 `lexicon.entry_count`；不写 `default_anchor`、不写 `frequency_*` |

## 7. `start-vocab.ps1` 自动 `upgrade head` 的发布风险（检查结论）

### 7.1 机械核对（非文档转述）

- **全仓库唯一的脚本级 alembic 调用**是 `scripts/start-vocab.ps1:64`：`& $python -m alembic -c alembic.ini upgrade head`，**无条件执行**。
- 该脚本内**不存在**任何 `backup` / `verify` / `rehearsal` / `current` / `revision` 判断（逐行核对，只有健康检查、venv、pip、node_modules、env 文件、进程退出这些 `if`）。
- `start-vocab.bat`（桌面快捷方式目标）以**无参数**方式调用它，因此用户双击一次就一定会走迁移路径。
- 该脚本被 `PROJECT_ROADMAP.md:685/706/961`、`AI_DEVELOPMENT_GUIDE.md:136` 与迁移 runbook §0.1 明确记为已知陷阱；`docs/2026-09-22-migration-history-forensics.md:21` 还把它列为事故路径 F-01/F-02。

### 7.2 部署一个含 `0008` 的版本会发生什么

双击启动 → `upgrade head` 隐式应用 `0008` → 拉起 uvicorn。**四闸门一个都没有**：没有 rehearsal（本次预演只在手动运行时发生，与应用启动无关）、没有备份、没有显式 revision、没有迁移后核验。而且因为应用自己的启动校验是"代码 head == 数据库 revision"，迁移完成后**恰好通过**，所以没有任何地方会提示"刚刚发生了一次迁移"。

更尖的一点：SQLite 上 Alembic "assume non-transactional DDL"（本次预演输出可见）。若 `0008` 的四次建表在中途失败，会留下**部分建表 + revision 未推进**的状态，下次启动重试即 "table already exists"，应用起不来——而此时**没有迁移前备份**可退。

### 7.3 对 `0008` 的具体评估与残余风险

- 就 `0008` 本身而言数据风险**低**：本次预演证明它只加表、不动既有行，且 `0007` 基线在迁移后仍然有效。
- 但**"只加表"是这一版的性质，不是这个机制的性质**。下一张涉及回填或重建的 migration 会继承完全相同的隐式路径。
- 现有缓解是**程序性的、且是 0007 专属的**：`docs/0007-production-migration-runbook.md` 与 checklist 要求"发布窗口内不得启动应用（含桌面快捷方式）"，并在 Step A6 确认 `alembic current` 已是目标 revision 后才放行。它依赖人记得读文档，且没有针对 `0008` 的同级 runbook/checklist。

**结论：这是尚未关闭的发布阻断项。** 代码层面未加固（本次不改启动器），建议的最小加固形态是：启动器先比较 `数据库当前 revision` 与 `代码 head`，**相等则完全照旧**；不等且库非空时**拒绝启动**并打印将应用的迁移与 runbook 指引，仅允许通过显式参数（如 `-MigrationRevision <显式 revision>`）放行。这样正常使用零变化，而"一次双击等于一次无备份隐式迁移"变成机械上不可能。**该加固需要自己的设计与针对 PowerShell 启动器的测试，本次不作为切片的一部分实施。**

本节由**独立 worktree** 上的联合评审写入，对象是 `codex/phase-2-9-concise-meaning` @ `78e077a`（含 `0008`、`0009`、目标库只读预检与简短释义）。所有缺陷都**先写出可复现的失败测试**，再改实现；每条都在下文写明复现方式。**生产库没有被打开写入或迁移**，本节修复后仍在同一分支上。

### 10.1 阻断项：重算摘要可以把"没有来源这么说"的释义写进公共词条

**症状**：`plan_sha256` 只能发现**误改**，它不是签名——谁改了计划都能重算它。而写入值 `entries[].default_snapshot` 此前**从不**被重新推导：`_reverify_evidence` 只把 `evidence[].raw_value` 与来源文件逐条比对。于是手工改过 `default_snapshot` 并重算摘要的计划会被**接受**：`lexicon_entry` 存下编造的释义，而 `entry_source_evidence` 把**真实的**来源值记成 `decision=selected`。审计链与它声称证明的内容互相矛盾——正是 Phase 2.9 存在的理由。

**为什么算缺陷而不是边界**：服务自己的 docstring 已经写明补救办法是"重新预览，绝不是手改计划"，授权元数据层也**正是**为这个"重算摘要的人"加固（`incomplete_provenance` 在服务层再拒一次）；只有写入值这一层漏了，而且 `_reverify_evidence` 的 docstring 声称它检查的是"这份计划将会写入的那个值"。

**修复**：`_reverify_written_values`（`backend/app/services/public_lexicon_confirm.py`，由 `_reverify_evidence` 调用，预检共用同一入口）：

| 写入项 | 与什么比对 |
|---|---|
| `source_meanings` | 计划自己声明选中的定位点（`default_evidence.meaning`）在该计划 `evidence` 里的值，**按序、去重后逐项相等** |
| `source_raw` | 主来源定位点处的**来源文件原样整行**（因此对的是文件，不是计划） |
| `word` / `phonetic` / `part_of_speech` | 必须是声明选中的值**之一**（一个裁定可以引用多行，只存第一条，所以不要求唯一） |
| `default_snapshot` 不是对象 | 拒绝，而不是抛 `TypeError` |

`no_default` 裁定确实什么都不选，因此声明为空时不做约束——这也是这项检查不会误拒合法计划的原因。

**回归测试**（先在 `78e077a` 上确认失败——三条都是 `Failed: DID NOT RAISE ConfirmRefused`，第四条是 `TypeError`）：

- `test_a_recomputed_digest_cannot_smuggle_a_default_no_source_states`
- `test_a_recomputed_digest_cannot_point_a_default_at_another_source_value`
- `test_a_recomputed_digest_cannot_rewrite_the_primary_raw_line`
- `test_a_malformed_snapshot_is_refused_rather_than_crashing`

**边界（仍然挡不住）**：`source_locator` 是人可读的自由文本，代码不核对它是否真的对应某个行号；`derivation_note` 的内容也不被校验。这两条与简短释义切片 §8 的"挡不住"同一性质，需要人复核，代码只保证"值与计划自己的证据一致"。
