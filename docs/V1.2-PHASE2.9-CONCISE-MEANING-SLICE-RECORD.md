## 本轮的环境事实（必须写明，不粉饰）

- 本次全部门禁运行在 DSH 文件沙箱内。沙箱下 Windows 上 `tempfile.mkdtemp` 与 pytest basetemp 使用的 `mode=0o700` 会被 CPython 转成受限 DACL，随后连自己刚创建的目录都打不开（`PermissionError: [WinError 5]`）。为让测试与子进程 alembic 正常运行，本轮用了一个**仓库外**的 `sitecustomize.py`（通过 `PYTHONPATH` 注入），把 `os.mkdir` 的 mode 放宽回 Windows 默认的 `0o777`。该文件不在仓库内，也没有被本切片提交；它不改变任何被测语义。
- `npm ci --offline` 需要执行依赖的 lifecycle 脚本（esbuild postinstall），该脚本在沙箱下以管道捕获自身 stdio 时被拒绝（`EPERM`/`-4048`）。本轮以一次显式放宽权限完成安装；安装结果 280 packages、0 vulnerabilities。安装日志提示 esbuild 的 `postinstall` 未被运行（`allow-scripts`），`vitest`、`vite build` 与整套门禁仍正常工作。
- 原样 `scripts/check.ps1` 必须**不加流重定向**地运行：把它的 stderr 合并进管道会让 PowerShell 5.1 在 npm 的普通 stderr 警告上按 `$ErrorActionPreference='Stop'` 终止脚本（表现为在"frontend tests"处静默退出且不打印 `FAILED:`）。不带重定向时脚本正常跑完并 **exit 0**。这是运行方式问题，不是门禁失败。

## 剩余阻断

1. **`0008` 与 `0009` 都未发布。** 两者必须一起发布；发布前若 `0008` 改号或改内容，`0009` 的 `down_revision` 必须跟着改（有测试兜底）。
2. **主词表与三份来源的授权仍未闭合。** 本切片不批准任何来源的 `use_scope` / `display_scope`，也没有一份带可机读 `provenance` 的真实来源清单。20 词草案（`codex/phase-2-9-provenance-rehearsal` @ `13131cd`）里 P09、P12、P14–P18 待负责人逐词确认；本轮**没有**把这些值写进任何数据库。
3. **"简体"没有被机械化校验。** 本切片要求非逐字引用必须声明改了什么并保留来源定位，但不检测文本是否确为简体；`derivation_note` 的内容也不被校验。见设计 §8。
4. **学习页「核心释义」与「最小语义锚点」并存**的视觉与语义重叠未裁定（设计 §5.3、§9）。
5. **真实来源下的复核节奏未验证**：propose/status/confirm 只在合成数据上跑通。
6. **一个 40 字上限被写进数据库 CHECK**：若产品口径要放宽，需要一次迁移。

## 联合评审的修复（2026-09-26）

独立 worktree 上的联合评审针对 `78e077a` 复现并修掉了三个真实缺陷。设计文档 §7.1 与上面"交付物"表里原先记的 **37 项**是过时计数：`78e077a` 收尾时已增到 **39**，本轮再补 2 项，实测 **41 collected**。

### 1（真实、契约级）：`propose()` 不是"全有或全无"

`ConciseMeaningRefused` 的 docstring 承诺"在任何行被加入之前抛出，因此拒绝让数据库保持原样"，但三个检查（证据归属、来源措辞吻合、已确认位置冲突）跑在**写入循环内部**，只有 `_validate` 在循环前。于是：

- 一次调用里第 1 条合法、第 2 条被拒 → 第 1 条**留在库里**（连同它的 `proposed` 历史）；
- 更严重的一种：某位置上已有**已确认**显示值、另一位置有候选，被拒的调用会**先把已确认值改成 `rejected`（撤回），再抛异常** —— 页面上正在显示的值被撤掉了。

CLI 掩盖了它（`session.rollback()`），所以用户看不到；但服务契约不成立，任何"捕获拒绝后提交"的调用方都会保留半份提案。

**修复**：把三处检查**全部提前**到第一次写入之前（`prepared` 列表），写入循环只做写入。测试：

- `test_a_refused_proposal_writes_none_of_its_siblings`
- `test_a_refused_slot_conflict_does_not_withdraw_the_displayed_value`

两项都**先在 `78e077a` 上跑成失败**（`git stash` 掉修复后重跑仍失败），且断言**不回滚会话**——被 flush 但未提交的行正是这条承诺所指的东西，回滚会让测试失去意义（第一版测试就因为回滚而假通过）。

### 2（真实、次要）：确认人只写第一个位置的那位

`ConciseMeaningList` 之前用 `meanings[0].confirmed_by` 给**整组**释义署名。不同位置可以由不同管理员确认，于是第二个会被记到没看过它的人头上。改为列出**去重后的全部确认人**。测试 `names every confirmer, not just the first slot's`。

### 3（真实、次要，且与"空数组"语义冲突）：文章页回答 `concise_meanings: []`

`api/articles.py` 的两处 `word_dict_from_view` 没有传短释义，而 `word_dict_from_view` 的默认值是空列表——于是**有**已确认短释义的词在文章测试/查词响应里也回答 `[]`。客户端无法区分"这个端点没加载"和"确实没有"，正是 `helpers.py` 注释里说空数组**不能**被这样用。阅读页的测试答案因此仍显示长释义。

**修复**：两处都传入真实值；并把 `word_dict_from_view` 的 `concise_meanings` 参数**去掉默认值**，让将来忘记传参的调用方直接报错，而不是安静地发出一个假的"没有已确认值"。测试 `test_every_word_response_reports_the_confirmed_value_or_nothing`（同时断言缺参是 `TypeError`）。

### 4（记录修正）：前端把"来源位置"渲染成存在性判断

该组件按"字段非空"渲染来源位置，没有看 `is_supplement`。数据库 CHECK 使"补充 + 来源指针"这一形状不可表示，所以现在不可达；但改为同时看标记是零成本的，客户端因此不必依赖服务端才能保持诚实。测试 `does not print a source position for a supplement even if one is present`。

**本切片未做**：真实来源、授权、20 词人工裁定、真实数据上的 propose/confirm/status 节奏（与上面"剩余阻断"同）。
