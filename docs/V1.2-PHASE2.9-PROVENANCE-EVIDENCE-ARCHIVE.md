## 2. 保全方法与"不覆盖"保证

1. **先算后拷**：对每个源文件先取 `SHA-256` 与字节数；
2. **不覆盖**：目标文件已存在时**不复制**，记为 `SKIPPED_EXISTS`（本轮 0 例，归档目录是新建的）；
3. **拷后复算**：复制完成立刻重算目标文件的 `SHA-256` 与字节数，与源不一致则记 `MISMATCH`；
4. **保留原文件**：全程只用 `Copy-Item`，没有 `Move-Item`、没有 `Remove-Item`；
5. **独立复算**：`verify_evidence.ps1` 重新读清单，**对两侧同时重新取摘要**（因此它不依赖第 1 步的记录），
   并检查归档里有没有"清单未记录的文件"。

复跑命令（两条，都在工作区根执行）：

```powershell
pwsh -NoProfile -File test-artifacts\phase29-provenance-evidence\_manifest\copy_evidence.ps1
pwsh -NoProfile -File test-artifacts\phase29-provenance-evidence\_manifest\verify_evidence.ps1
```

> **踩到的坑（写下来以免复跑者重复）**：这两个脚本必须是**纯 ASCII**。
> 工作区路径含中文，而 Windows PowerShell 读取**无 BOM 的 `.ps1`** 时会按 ANSI 解码，
> 中文字面量会被拆坏（实测报错 `Access to the path 'p29x-rehearsal-package' is denied`，
> 路径被解码成 `D:\鑳屽崟璇峸eb\…`）。因此脚本用 `$PSScriptRoot` 反推工作区，不写中文路径字面量，
> 并且用 `.NET` 的 `UTF8Encoding($false)` 写清单（避免 BOM 干扰解析）。

## 5. 目标目录是否仍需另做备份

**需要，而且现在就应纳入既有备份习惯。** 三条理由：

1. **它不在 Git 里**：`.gitignore:43` 使整个 `test-artifacts/` 不进版本库，
   所以"把仓库推到远端"**不会**带走这个目录 —— 它对 Git 是隐形的。
2. **它只存在于这一台机器的一个工作区**：若工作区被删除、被重新克隆、或被 `git clean -xfd` 清理，
   归档会**一起消失**（`git clean -xfd` 会删掉被忽略的目录，这是最现实的风险）。
