## 实现边界

### 新增只读服务：`backend/app/services/public_lexicon_plan.py`

| 能力 | 说明 |
|---|---|
| 角色分层 | 每个来源必须声明 `role`；恰好一个 `primary`。**成员与顺序只来自 primary 来源**，补充来源不能新增词条 |
| 成员规则 | `primary_source_first_occurrence_v1`：重复词保留首次出现的位置，两次出现都作为证据保留 |
| 冲突检测 | `strip_distinct_v1`：`strip()` 后精确比较，≥2 个不同非空取值即为冲突（`meaning`/`phonetic`/`part_of_speech`） |
| 无歧义默认 | `agreeing_evidence_all_cited_v1`：唯一取值时默认该值，并引用**所有**给出该取值的证据行，**不在地来源之间静默取舍** |
| 人工裁定 | `select` / `no_default` / `defer` / `exclude_word` / `exclude_row`；陈旧定位是**错误**而非空操作 |
| 阻断 | 未决冲突、缺必填字段、`defer`、必填字段 `no_default`、不可解析行未承认、同文件同映射重复声明、来源文件级问题 |
| 幂等契约 | 计划自带 `idempotency` 块，声明 run / source / entry / evidence 四层键；证据键**不含 `source_id`** |
| 摘要 | `plan_sha256` 只覆盖决定"会写什么"的字段；`created_utc` / `run_id` / `manifest_file` 在摘要之外 |

**不拼接、不覆盖**：同一字段的每个来源原值逐条保留在 `evidence` 里，按 `(source_id, line, raw_value)` 稳定排序；默认值只能来自人工 `select` 或无歧义的唯一取值，且都能通过 `default_evidence` 回到 `(source_id, line)`。`source_raw` 固定为 primary 行原始整行，**永不改写、永不跨来源拼装**。

### 新增 CLI（只读，不打开应用数据库）

```
python -m app.cli public-lexicon plan MANIFEST \
    --source-root DIR --decisions DIR/decisions.json \
    --plan NEW.json --target-lexicon NAME [--require-ready]
```

- 计划文件用独占创建写出，**拒绝覆盖**既有计划（计划是证据）。
- 退出码 `0` 写出成功 / `2` 生成失败 / `1`（加 `--require-ready` 且 `confirmation_ready=False`）。
- 来源文件、清单、裁定文件都必须解析到 `--source-root` 内；越界以 `outside_source_root` 拒绝。
- **`confirmation_ready=True` 只表示这份计划自身已裁定完毕，不构成写入授权。** 确认入库需要另一次管理员本人身份与当前口令复核，本切片不实现。

### 4. 归一化与 `source_raw`：核对结论是"未改动"

来源报告 §7.1 的小标题写明它自己的口径：**"重合矩阵（归一化：只保留字母数字并小写）"**。那是**调研用于比较两套数据集的规则**，不是本产品的词条身份规则。逐条核对：
