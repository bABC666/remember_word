## 3. 修掉的缺陷

### 3.1 阻断项：重算摘要可以把"没有任何来源这么说"的释义写进公共词条

`plan_sha256` 只能发现**误改**，不是签名。而写入值 `entries[].default_snapshot` **从不**被重新推导，`_reverify_evidence` 只比对计划里的 `evidence[].raw_value` 与来源文件。于是手工改过 `default_snapshot` 并重算摘要的计划被**接受**：`lexicon_entry` 存下编造的释义，而 `entry_source_evidence` 把真实的来源值记成 `decision=selected` —— 审计链与它声称证明的内容互相矛盾。

服务自己的 docstring 已写明补救是"重新预览，绝不是手改计划"，授权元数据层也**正是**为这个"重算摘要的人"加固过；只有写入值这一层漏了。**已修复**：写入值必须能由计划自己声明选中的证据重新推出（详见 `V1.2-PHASE2.9-CONFIRM-WRITE-SLICE-RECORD.md` §10）。四条回归测试先在 `78e077a` 上确认为失败。

### 4.1 本轮的门禁运行环境（必须写明，不粉饰）

- 门禁在 DSH 文件沙箱下运行时，`tempfile.mkdtemp` / pytest basetemp 使用的 `mode=0o700` 会被 CPython 转成受限 DACL，随后连自己刚建的目录都打不开（`WinError 5`，表现为 `test_csrf.py`/`test_spa_fallback.py` 收集期报错）。本轮用了一个**仓库外**的 `sitecustomize.py`（经 `PYTHONPATH` 注入，路径 `…\.worktrees\.dsh-runner-shim\`）把 `os.mkdir` 的 mode 放宽回 Windows 默认值。它不在仓库内、不进入提交，也不改变任何被测语义（仓库里没有任何断言依赖目录权限位）。
- 前端各步骤需要进程管道：受限模式下 esbuild 会以 `spawn EPERM` 失败。本轮在放开的模式（`danger-full-access`）下运行完整门禁。
- **这两项都是运行环境问题，不是门禁结果**：在正常权限的 Windows 上，不加任何 shim 的原样 `check.ps1` 即可跑完。
