- `Z oldid:行`：`test-artifacts/phase29-provenance-evidence/kaoyan-vocab-research/rehearsal/pilot/zh-pinned-wikitext-300.json` 内该固定修订的 wikitext 行号。逐行抽取索引为同目录 `v4-extraction-300.json` 的 `pages[oldid].candidates`；**以下引号内保留原文行的相关片段**，完整版以固定修订原文为准。`oldid` 是页面修订，不等于该抽取器已正确判断词性或含义。

## `key` 的优先核对结果

NETEM 原始词表 `raw/netem_full_list.json` 有 `key`（序号 766）；其“钥匙、关键”在该来源的**释义列**，本轮不把该列当释义依据。保全的 `reports/zhwiktionary-full-coverage.json` 对 `key` 记录了 `oldid=9715314`、页面存在但 `defs=[]`；300 词固定原文包和转换的 `wikdict.csv` 都不含 `key`。因此目前**没有同一固定来源原文中的“钥匙／关键”可供逐义回查**，本轮不把它纳入 20 个已试裁定词，也不冒称 Z 缺这个义。下一步若仍优先选 `key`，须先把该 oldid 原文和对应的 WikDict 原条目按固定版本保全，再判断名词“钥匙／关键”与形容词等词性。

## 结构与本轮检查结果

- 现有 `entry_concise_meaning` 以 `lexicon_entry_id + display_order` 限**每词最多 3 行**，没有词性列；`lexicon_entry.part_of_speech` 也是单字符串。现结构不能忠实存储或校验“**每词性 1–3 条**”。本表按词性写，**未压成每词 3 条**。如 `play`、`prior`、`mutter`、`cast`，未来实现必须另行设计词性分组、词性证据与每组位次；本轮不改实现。
- 这 20 词是**语义试裁定**，其中第 15、17、20 词有阻断性来源／词性缺口。AI 新增且无来源支持的条目只有 `fertiliser → 肥料`，状态为待人工确认、不可展示。其他衍生项须随原文位置保留修改说明。
- 只对这份文档的词数、引用行是否存在、每词性候选数和 Git 差异做直接检查；没有跑完整门禁、读写生产库、迁移或批量裁定。
