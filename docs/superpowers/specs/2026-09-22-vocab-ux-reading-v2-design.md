# 拾词 V1.1：导入、OCR 与阅读辅助设计

## 目标

修复多图导入的覆盖与不可删除问题，缩短 OCR 等待时间，明确 DeepSeek 实际模型，并把阅读页扩展为“英文阅读—按需查词—全文翻译—保存记录—生词入库”的闭环。所有新增记录仍以 SQLite 为唯一事实来源。

## 1. 导入工作流

- 上传前连续拖入或选择图片时，合并到当前待上传列表；按文件名、大小和最后修改时间去重。
- 每张待上传图片提供移除按钮。
- 已创建但尚未确认的批次可以继续追加图片、移除单张图片或放弃整个批次。
- 数据库采用软删除标记；原文件和 OCR 原始结果不物理销毁，避免误操作导致不可恢复。
- 已进入候选校对时，不允许单独删除图片，以免候选词与原始来源失去一致性；用户可以放弃整个未确认批次，或取消候选选择。
- 新增图片后，已完成图片的 OCR 结果继续复用，只识别新增或失败图片。

## 2. OCR 性能与 AI 清洗

- PaddleOCR 引擎按语言和设备参数在进程内缓存，避免每个批次重复加载模型。
- 手机超大图片只为 OCR 生成最长边 2200px 的临时副本；原图、hash 和路径保持不变。
- 批次重试时跳过已有成功 OCR 原始结果的图片。
- DeepSeek 结构化阶段负责排除页码、栏目标题、例句编号等非词条噪声，合并断行，保留音标，并把不同词性/义项拆成独立数组项。
- AI 只产生候选和 learning 字段，不能改写 OCR 原文、图片记录或人工修改。

## 3. DeepSeek 模型

默认模型改为官方 API 名 `deepseek-flash`，设置页显示其对应版本“DeepSeek V4.1-Flash”。旧配置 `deepseek-chat` 在读取时安全映射到新默认名；仍允许用户切换到 `deepseek-v4-pro` 或填写兼容服务的自定义模型名。

## 4. 音标、义项与字体

- 音标继续保存在独立 `phonetic` 字段，Unicode/IPA 原样显示，不混入释义。
- 义项展示组件识别 `1. / 1) / ①` 等编号，把同一字符串内的多义项按行展示；新导入 prompt 同时要求每个义项单独返回。
- 独立单词改用 Aptos/Segoe UI/Arial 一类日常英文书写字体；长文使用 Cambria/Charter 一类稳定阅读字体。

## 5. 使用说明

- 首次使用显示一次欢迎说明，是否看过保存在 SQLite `app_setting` 中。
- 侧栏长期保留“使用说明”按钮，可随时重新打开。
- 内容说明 Source/Learning/History 的边界、主动回忆评分、阅读复现、AI 的辅助角色、数据与备份位置。

## 6. 阅读辅助

- 正文按英文词元渲染为可点击单词；点击后显示释义卡片。
- 已在词库中的词优先返回本地 anchor 和原书释义，不调用 AI。
- 未知词调用独立 AI lookup service，结果经 Pydantic 校验后写入 `article_word_lookup`，后续点击直接读取 SQLite 缓存。
- 全文翻译按需生成，译文、时间和 AI 原始结构化结果写入 article；正文默认仍只展示英文。
- 查词历史在文章下方展示。未知词可加入词库：文章原句进入 `source_raw`，AI 释义进入 anchor/semantic_note，并标记需人工核对；同时建立文章暴露关联。

## 7. 错误与降级

- OCR、查词、全文翻译任一步失败都不能覆盖已有数据。
- DeepSeek 不可用时，背词、OCR 原文查看、人工校对、文章阅读和已有查词记录仍可使用。
- 添加重复生词时复用已有词条，不生成重复 Word。

## 8. 验收

- 连续拖入两次后图片数量累加，单张可移除。
- 批次图片可追加、可软删除；已有 OCR 结果重试不重复执行。
- OCR 大图使用临时缩放副本，原图不变。
- 设置页明确显示 API 名与实际模型版本。
- 音标正确显示，多义项逐行显示，单词字体更新。
- 首次说明与永久入口均可用。
- 阅读正文可点词、保存查词、生成/保存全文翻译、把生词加入词库，并能在重启后恢复。
